움직임 이름 9가지

"부드럽게 움직여줘" 말고 움직임의 이름으로 말해요

01

이즈 인 Ease-in

처음엔 느리게 출발해서 점점 빨라지는 움직임입니다. 끝에서 가장 빠르기 때문에 "탁" 하고 끝나는 느낌이 납니다. CSS 값은 ease-in입니다.

언제 쓰나화면 밖으로 사라지는 요소. 알림이 위로 날아가거나 카드가 옆으로 치워질 때.

AI에게 이렇게삭제된 카드가 오른쪽으로 사라질 때 ease-in 으로 점점 빨라지게 해줘

20년차 메모사용자가 버튼을 누르자마자 이즈 인으로 반응하면 처음 몇십 밀리초가 굼떠서 "반응이 느리다"고 느낍니다. 들어오는 움직임에는 쓰지 말고 나가는 움직임에만 쓰세요.

02

이즈 아웃 Ease-out

처음엔 빠르게 출발하고 끝에서 천천히 멈추는 움직임입니다. 누르자마자 반응하고 부드럽게 자리를 잡아서, 화면에 들어오는 요소의 기본값입니다.

언제 쓰나메뉴가 열리고, 모달이 등장하고, 토스트가 올라오는 것처럼 새로 나타나는 모든 요소.

AI에게 이렇게사이드 메뉴가 열릴 때 0.3초 ease-out 으로 부드럽게 멈추게 해줘

20년차 메모CSS 기본값 ease 는 이즈 아웃에 가까운 곡선이라 대충 써도 나쁘지 않지만, 시간을 길게 잡으면 끝이 질질 끕니다. 0.2~0.4초 안에서 쓰고, 0.5초를 넘기면 사용자가 기다리는 느낌을 받는지 확인하세요.

점선을 살짝 넘었다가 돌아옵니다

03

스프링 Spring

목표 지점을 살짝 넘어갔다가 용수철처럼 돌아와 멈추는 움직임입니다. 시간이 아니라 탄성(stiffness)·감쇠(damping) 값으로 정하는 게 원래 방식이고, CSS에서는 y 값이 1을 넘는 cubic-bezier로 흉내 냅니다.

언제 쓰나좋아요 버튼, 시트가 올라올 때, 알림이 튀어나올 때처럼 가볍고 생기 있는 느낌이 필요한 곳.

AI에게 이렇게하단 시트가 올라올 때 살짝 넘쳤다가 돌아오는 스프링 애니메이션을 적용해줘

20년차 메모금융·의료처럼 차분해야 하는 화면에 스프링을 쓰면 장난스러워 보입니다. 넘치는 폭이 크면 요소가 화면 가장자리를 벗어나 잘리니, 가장자리에 붙은 요소는 여유 공간부터 확인하세요. iOS는 스프링이 기본 감각이고 웹은 직접 값을 정해야 합니다.

04

바운스 Bounce

공이 바닥에 떨어져 점점 낮게 여러 번 튀는 움직임입니다. 스프링이 목표를 한 번 지나쳤다 돌아오는 것이라면, 바운스는 바닥에 부딪혀 튕기는 느낌입니다.

언제 쓰나빈 화면의 안내 아이콘, 스크롤 아래로 유도하는 화살표, 게임·어린이 서비스처럼 장난기가 필요한 곳.

AI에게 이렇게완료 아이콘이 위에서 떨어져 두세 번 바운스하며 멈추게 해줘

20년차 메모바운스를 무한 반복으로 두면 시선을 계속 빼앗아 글을 읽을 수 없습니다. 한두 번만 튀고 멈추게 하세요. 어지러움을 느끼는 사용자를 위해 시스템의 "동작 줄이기" 설정이 켜져 있으면 끄는 것도 필수입니다.

05

순차 등장 Stagger

여러 요소가 한꺼번에가 아니라 0.05~0.15초씩 시간차를 두고 하나씩 나타나는 움직임입니다. 스태거라고 부르고, 눈이 위에서 아래로 따라가며 구조를 파악하게 도와줍니다.

언제 쓰나목록·카드 그리드가 처음 뜰 때, 온보딩 문구가 차례로 나올 때, 메뉴 항목이 펼쳐질 때.

AI에게 이렇게카드 목록이 나타날 때 항목마다 0.1초씩 시간차를 둔 순차 등장(stagger)을 넣어줘

20년차 메모항목이 30개인데 0.1초씩 늦추면 마지막 카드가 3초 뒤에 뜹니다. 화면에 보이는 첫 5~8개에만 적용하고 나머지는 한 번에 보여주세요. 개발자에게는 "순서마다 지연 시간을 곱해서 준다"고 말하면 바로 통합니다.

Fade

06

페이드 Fade

투명도만 0에서 1로(또는 반대로) 바꿔 서서히 나타나거나 사라지게 하는 가장 단순한 움직임입니다. 위치와 크기는 그대로입니다. 나타나면 페이드 인, 사라지면 페이드 아웃입니다.

언제 쓰나토스트 메시지, 툴팁, 이미지 로딩 완료, 화면 안에서 내용만 바뀔 때.

AI에게 이렇게툴팁이 0.2초 페이드 인으로 나타나고 사라질 땐 페이드 아웃되게 해줘

20년차 메모페이드 아웃이 끝나도 요소는 여전히 거기 있어서 클릭이 먹히거나 스크린 리더가 읽을 수 있습니다. 투명해진 뒤에 화면에서 실제로 치우는 처리(display, 접근성 숨김)가 빠지는 경우가 많습니다.

Slide

07

슬라이드 Slide

화면 가장자리에서 밀려 들어오거나 밀려 나가는 움직임입니다. 어느 쪽에서 오는지가 곧 "이 요소가 원래 어디에 있는가"를 알려줍니다. 아래에서 오면 슬라이드 업, 옆에서 오면 슬라이드 인입니다.

언제 쓰나사이드 메뉴, 하단 시트, 알림 배너, 캐러셀 넘기기.

AI에게 이렇게알림 배너가 화면 위에서 슬라이드 다운으로 내려오고 3초 뒤 다시 올라가게 해줘

20년차 메모들어오는 방향과 나가는 방향이 다르면 사용자는 공간 감각을 잃습니다. 왼쪽에서 왔으면 왼쪽으로 돌아가게 하세요. 그리고 슬라이드되는 거리가 길수록 시간도 늘려야 같은 속도로 느껴집니다.

Zoom

08

확대 전환 Zoom transition

작은 썸네일이 눌린 자리에서 화면 전체로 커지며 상세 화면이 되는 전환입니다. 닫으면 반대로 줄어들어 원래 자리로 돌아갑니다. 공유 요소 전환과 달리 요소 하나가 아니라 화면 전체가 커집니다.

언제 쓰나사진 갤러리에서 사진 열기, 앱 아이콘에서 앱 열기, 지도에서 장소 카드 열기.

AI에게 이렇게갤러리 썸네일을 누르면 그 위치에서 화면 전체로 커지는 확대 전환을 넣어줘

20년차 메모닫을 때 원래 자리로 정확히 돌아가지 않으면 전환 전체가 가짜처럼 보입니다. 스크롤 위치가 바뀌었거나 그 썸네일이 목록에서 사라진 경우를 꼭 점검하세요. 웹에서는 뒤로 가기 버튼과도 맞아야 합니다.

09

공유 요소 전환 Shared element

두 화면에 모두 있는 같은 요소(예: 상품 사진) 하나가 화면이 바뀌는 동안 새 자리로 날아가 커지거나 줄어드는 전환입니다. 나머지는 사라지고 하나만 이어져서 같은 물건이라는 연결감을 줍니다. 히어로 전환(Hero)이라고도 합니다.

언제 쓰나목록의 상품·음악 앨범 사진이 상세 화면의 큰 사진으로 이어질 때.

AI에게 이렇게목록의 상품 이미지를 누르면 같은 이미지가 상세 화면 상단으로 이어지는 공유 요소 전환을 만들어줘

20년차 메모짝이 되는 요소의 이름표(식별자)를 양쪽 화면에서 똑같이 붙여야 하는데, 개발자가 이걸 빠뜨려 전환이 그냥 깜빡임으로 끝나는 일이 흔합니다. 목록 사진과 상세 사진의 가로세로 비율이 다르면 중간에 찌그러지니 시안에서 미리 정하세요.

캡쳐엔 없지만 알아둘 용어

움직임을 이야기할 때 가장 기본이 되는 말들입니다.

가로 = 시간, 세로 = 이동한 정도

10

이징 Easing

움직임의 속도 변화 방식을 부르는 말입니다. 이즈 인, 이즈 아웃, 스프링은 모두 이징의 종류이고, 그래프로 그리면 곡선이 됩니다. CSS에서는 cubic-bezier(x1, y1, x2, y2) 네 숫자로 곡선을 직접 만듭니다.

언제 쓰나"자연스럽게 해줘"를 구체적으로 바꿔 말할 때. 이징 이름이나 cubic-bezier 값을 지정하면 결과가 매번 같아집니다.

AI에게 이렇게모든 전환의 이징을 cubic-bezier(0.2, 0, 0, 1) 하나로 통일하고 변수로 빼줘

20년차 메모요소마다 다른 이징을 쓰면 화면이 산만해집니다. 프로젝트에 "들어올 때, 나갈 때, 강조할 때" 세 가지 정도만 정해 이름을 붙여 두세요. 디자인 툴의 이징 이름과 개발자가 쓰는 값이 다를 수 있어 숫자로 주고받는 게 안전합니다.

0.3초
1.2초

11

지속 시간 Duration

움직임이 시작해서 끝날 때까지 걸리는 시간입니다. CSS의 transition-duration · animation-duration이며 보통 밀리초(ms) 단위로 말합니다. 같은 이징이라도 시간이 달라지면 전혀 다른 느낌이 됩니다.

언제 쓰나작은 반응(버튼 눌림)은 100~200ms, 화면 안 요소의 이동은 200~400ms, 큰 화면 전환은 300~500ms 안팎을 출발점으로 삼습니다.

AI에게 이렇게버튼 눌림은 150ms, 모달 등장은 300ms 로 지속 시간을 나눠서 지정해줘

20년차 메모디자이너가 "빠르게"라고만 쓰면 개발자마다 0.1초도 1초도 됩니다. 반드시 ms 숫자로 적으세요. 그리고 화면이 클수록, 움직이는 거리가 길수록 더 길게 잡아야 같은 속도로 느껴집니다. 모바일은 PC보다 조금 짧게 가는 편이 좋습니다.

12

리니어 Linear

출발부터 도착까지 속도가 일정한 움직임입니다. 가속과 감속이 없어서 기계적이고, 실제 물체의 움직임과는 거리가 있습니다. CSS 값은 linear입니다.

언제 쓰나로딩 스피너의 회전, 무한히 흐르는 배경, 진행 바처럼 속도가 일정해야 맞는 반복 움직임. 투명도·색 변화에도 어울립니다.

AI에게 이렇게로딩 스피너는 linear 로 일정하게 돌리고, 모달 등장은 ease-out 으로 해줘

20년차 메모이동·크기 변화에 리니어를 쓰면 "싸구려 PPT 애니메이션" 같은 느낌이 납니다. 반대로 스피너에 이즈 인아웃을 쓰면 돌 때마다 끊기는 듯 보입니다. 이동하는 것은 이징, 계속 도는 것은 리니어로 나누세요.
