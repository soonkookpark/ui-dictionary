01

푸시 Push

새 화면이 오른쪽에서 밀고 들어오고, 이전 화면은 살짝 왼쪽으로 밀려납니다. 화면이 한 칸 깊이 들어가는 이동이라 돌아올 땐 반대로 밀려 나갑니다. 내비게이션 스택(쌓기)이라고도 부릅니다.

언제 쓰나목록에서 상세로, 설정에서 하위 설정으로 들어가는 계층 이동.

AI에게 이렇게목록 항목을 누르면 상세 화면이 오른쪽에서 푸시로 들어오게 하고 왼쪽 위에 뒤로 가기를 넣어줘

20년차 메모iOS는 왼쪽 가장자리를 밀어 뒤로 가는 동작이 기본이라 푸시와 한 세트입니다. 안드로이드와 웹은 시스템 뒤로 가기 버튼·브라우저 뒤로 가기가 있으니 전환 방향이 그것과 맞는지 확인하세요. 같은 위계의 탭 이동에 푸시를 쓰면 길을 잃습니다.

B 새 글 쓰기

02

모달 등장 Modal present

새 화면이 아래에서 위로 올라와 이전 화면 위에 얹힙니다. 뒤 화면은 어두워지고 그대로 남아 있어서 "잠깐 다른 일을 하고 돌아온다"는 느낌을 줍니다. 푸시와 달리 깊이 들어가는 게 아닙니다.

언제 쓰나새 글 쓰기, 필터 선택, 공유하기처럼 하나의 독립된 작업을 끝내고 닫는 화면.

AI에게 이렇게글쓰기 버튼을 누르면 아래에서 올라오는 모달로 작성 화면을 열고 위에 닫기 버튼을 넣어줘

20년차 메모모달에서 또 모달을 여는 중첩이 가장 흔한 사고입니다. 닫는 방법(닫기 버튼, 아래로 내리기, 바깥 탭, Esc 키)이 서로 일치하는지, 작성 중인 내용을 닫을 때 "버릴까요?" 확인이 있는지 챙기세요.

03

페이드 스루 Fade through

이전 화면이 먼저 투명해져 사라지고, 새 화면이 살짝 커지며 나타납니다. 두 화면이 겹쳐 보이지 않는 것이 단순 크로스페이드와 다른 점이며, 머티리얼 디자인이 서로 관계없는 화면 사이에 권하는 방식입니다.

언제 쓰나하단 탭 사이 이동처럼 같은 레벨이면서 서로 상관없는 화면.

AI에게 이렇게하단 탭을 누르면 이전 화면이 페이드 아웃된 뒤 새 화면이 살짝 커지며 페이드 인되는 페이드 스루로 전환해줘

20년차 메모두 화면의 배경색이 다르면 중간에 번쩍이는 빈 화면이 보입니다. 배경은 고정하고 내용만 바꾸세요. 시간도 합쳐서 0.3초를 넘기면 탭 하나 누르는 데 답답해집니다.

B 상세 정보

04

공유 요소 Shared element

두 화면에 공통으로 있는 요소 하나가 새 자리로 날아가 이어지는 전환입니다. 나머지 내용은 바뀌어도 이 요소만은 같은 물건이라는 연결을 만들어 줍니다.

언제 쓰나목록의 썸네일이 상세 대표 사진이 될 때, 미니 플레이어의 앨범 사진이 전체 재생 화면으로 이어질 때.

AI에게 이렇게상품 목록의 썸네일이 상세 화면의 대표 이미지로 이어지는 공유 요소 전환을 넣어줘

20년차 메모요소의 시작과 끝 모양(비율·모서리)이 다르면 중간에 일그러집니다. 화면 위에 임시 복제본을 띄워 이동시키는 구조라 개발 난이도가 높은 편이니 "정말 이 전환이 가치 있는 한두 곳"에만 쓰자고 합의하세요.

A 목록

05

카드 확장 Card expand

눌린 카드가 그 자리에서 사방으로 넓어져 화면 전체를 덮고 상세가 됩니다. 카드와 상세가 하나의 면으로 이어지는 것이 특징이고, 머티리얼 디자인에서는 컨테이너 변환(container transform)이라고 부릅니다.

언제 쓰나기사·레시피·일정 카드를 눌러 전체 내용을 열 때. 카드 하나가 화면 하나로 이어지는 곳.

AI에게 이렇게카드를 누르면 카드가 화면 전체로 넓어지며 상세 내용이 나타나는 카드 확장 전환을 적용해줘

20년차 메모카드 안 글이 상세에서 위치가 바뀌면 글자가 떠다니며 어색합니다. 제목 위치를 맞추거나 카드 속 글은 먼저 사라지게 하세요. 닫을 때 카드가 목록의 같은 자리로 돌아가는지, 목록이 스크롤된 경우에도 맞는지 테스트해야 합니다.

A 앨범
B 사진

06

줌 Zoom

이전 화면이 확대되며 사라지고 새 화면이 작은 크기에서 제 크기로 커지는 전환입니다. 카메라가 안으로 쑥 들어가는 느낌이며, 화면 전체가 대상입니다. 요소 하나만 이어지는 공유 요소와 다릅니다.

언제 쓰나폴더·앨범·앱을 열어 그 안으로 들어가는 느낌이 필요할 때. 닫을 땐 반대로 줌 아웃.

AI에게 이렇게앨범을 누르면 이전 화면이 확대되며 사라지고 사진 목록이 줌 인으로 나타나게 해줘

20년차 메모화면 전체가 커지는 움직임은 멀미를 일으키기 쉽습니다. 확대 폭은 작게(1.1~1.3배 안팎), 시간은 짧게 잡으세요. 시스템의 "동작 줄이기"가 켜져 있으면 단순 페이드로 대체해야 합니다.

A 홈
B 오늘의 할 일

07

순차 등장 Stagger in

화면이 바뀐 뒤, 새 화면 안의 항목들이 한꺼번에가 아니라 위에서부터 시간차로 하나씩 나타납니다. 화면 전환 자체가 아니라 도착한 뒤의 연출이라서 다른 전환 방식과 함께 씁니다.

언제 쓰나온보딩 첫 화면, 대시보드 처음 진입, 검색 결과가 처음 뜰 때.

AI에게 이렇게화면이 열린 뒤 목록 항목이 0.12초 간격으로 위에서 아래로 순차 등장하게 해줘

20년차 메모매번 보는 화면에 쓰면 두 번째부터는 "빨리 보여줘"가 됩니다. 처음 진입할 때만 쓰거나 전체 시간을 0.5초 안으로 묶으세요. 데이터가 늦게 오는 항목까지 시간차를 두면 빈 칸이 먼저 보입니다.

08

탭 전환 Tab switch

같은 위계의 탭 사이를 오갈 때, 내용이 옆으로 밀리고 선택 표시(밑줄)가 따라 움직입니다. 탭 순서대로 좌우 방향이 정해지는 것이 특징입니다.

언제 쓰나상단 탭(추천/팔로잉), 세그먼트 컨트롤, 가로로 스와이프해서 넘기는 탭 화면.

AI에게 이렇게상단 탭을 누르면 내용이 탭 순서에 맞는 방향으로 밀리고 밑줄 표시가 함께 이동하는 탭 전환을 넣어줘

20년차 메모탭마다 스크롤 위치를 기억할지, 매번 맨 위로 보낼지를 정하지 않으면 개발자가 임의로 정합니다. 그리고 내용이 가로 스와이프로 넘어가는 화면에 가로로 스크롤되는 캐러셀을 넣으면 두 동작이 서로 싸웁니다.

09

시트 확장 Sheet expand

아래에서 올라온 시트가 처음엔 절반쯤만 보이다가 위로 끌어올리면 화면 전체로 커집니다. 바텀 시트(Bottom sheet)의 높이 단계를 중간(half)과 전체(full)로 나눈 것이며, 뒤 화면과 함께 볼 수 있다는 점이 모달과 다릅니다.

언제 쓰나지도 앱의 장소 목록, 음악 플레이어, 댓글 창처럼 뒤 화면을 보면서도 상세로 펼칠 수 있는 곳.

AI에게 이렇게장소 목록을 바텀 시트로 만들고 위로 끌면 절반에서 전체 화면으로 확장되게 해줘

20년차 메모시트 안 목록 스크롤과 시트 끌어올리기 제스처가 충돌하는 게 가장 큰 문제입니다. 시트가 전체까지 올라간 뒤에야 안쪽이 스크롤되게 정해 두세요. 웹에서는 드래그 손잡이만 믿지 말고 "펼치기" 버튼도 같이 두는 게 안전합니다.

10

팝 Pop · Back transition

푸시로 들어온 화면을 닫을 때 쓰는 반대 전환입니다. 현재 화면이 오른쪽으로 밀려 나가고 이전 화면이 제자리로 돌아옵니다. 들어온 길 그대로 되돌아간다는 규칙이 핵심입니다.

언제 쓰나뒤로 가기 버튼, 왼쪽 가장자리 스와이프, 안드로이드 시스템 뒤로 가기를 눌렀을 때.

AI에게 이렇게뒤로 가기를 누르면 현재 화면이 오른쪽으로 빠지는 팝 전환으로 이전 화면에 돌아가게 해줘

20년차 메모들어올 땐 푸시인데 나갈 땐 그냥 사라지는 화면이 의외로 많습니다. 시안에서 "열기"만 그리고 "닫기" 전환을 빠뜨린 탓입니다. 전환은 항상 열기와 닫기 한 쌍으로 정의하세요.

A 목록

11

스크림 Scrim

모달·메뉴·시트가 열릴 때 뒤 화면을 덮는 반투명한 어두운 막입니다. 딤(dim), 오버레이(overlay), 백드롭(backdrop)이라고도 부릅니다. 눈길을 앞쪽으로 모으고 뒤 화면은 지금 못 누른다는 걸 알려줍니다.

언제 쓰나모달, 바텀 시트, 사이드 메뉴, 확인 대화상자 뒤. 보통 검정 40~60% 투명도.

AI에게 이렇게모달 뒤에 검정 50% 스크림을 깔고, 스크림을 누르면 모달이 닫히게 해줘

20년차 메모스크림이 있는데 뒤 화면이 스크롤되거나 키보드로 눌러지는 사고가 잦습니다. 스크롤 잠금과 포커스 가두기(focus trap)까지 해야 진짜로 막힌 것입니다. 삭제 확인처럼 실수하면 안 되는 대화상자는 스크림 탭으로 닫히지 않게 하세요.

12

뷰 트랜지션 View Transitions API

웹 브라우저가 직접 제공하는 화면 전환 기능입니다. 바뀌기 전과 후의 모습을 브라우저가 사진처럼 찍어 두고 둘 사이를 자동으로 이어 줍니다. 같은 view-transition-name을 붙인 요소는 공유 요소 전환처럼 움직입니다.

언제 쓰나웹에서 목록→상세, 테마 전환, 정렬 바꾸기처럼 화면이 크게 바뀔 때 라이브러리 없이 전환을 넣고 싶을 때.

AI에게 이렇게목록에서 상세로 이동할 때 View Transitions API 로 썸네일이 이어지는 전환을 넣고, 지원하지 않는 브라우저에서는 그냥 이동하게 해줘

20년차 메모브라우저마다 지원 시점이 달라서 "안 되면 그냥 바뀌어도 아무 문제 없게" 설계해야 합니다. 전환을 기능의 필수 조건으로 삼지 마세요. 전환 중 사진이 한 장의 이미지로 굳어 있어서 그 사이에 영상이나 입력창은 눌러지지 않습니다.
