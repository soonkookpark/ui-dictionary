폼과 입력

눌러서 칸 상태를 확인해 보세요

01

텍스트 필드 Text field

글자를 한 줄 적는 기본 입력 칸입니다. 이름·제목처럼 짧은 값에 쓰며 텍스트 인풋(text input)이라고도 합니다. 여러 줄은 텍스트 영역이 따로 있습니다.

언제 쓰나이름, 닉네임, 상품명처럼 한 줄로 끝나는 값을 받을 때.

AI에게 이렇게이름 텍스트 필드에 위쪽 라벨을 붙이고, 포커스되면 테두리 색이 바뀌게 해줘

실무 팁안내 문구를 칸 안(플레이스홀더)에만 넣고 라벨을 없애면, 입력을 시작하는 순간 무엇을 적는 칸인지 사라집니다. 라벨은 칸 밖에 항상 보이게 두세요. 칸 높이는 손가락 기준 44pt 이상이 안전합니다.

원
kg

02

접두·접미 표시 Prefix · Suffix

입력 칸 앞이나 뒤에 붙는 고정 글자입니다. 사용자가 지울 수 없고 단위나 기호를 알려주는 용도라서, 칸 안의 글자와 구분됩니다. 앞에 붙으면 접두(Prefix), 뒤에 붙으면 접미(Suffix)입니다.

언제 쓰나금액의 "원", 무게의 "kg", 주소창의 "https://"처럼 단위·고정 문구가 있는 값.

AI에게 이렇게가격 입력 칸 오른쪽에 접미 표시로 "원"을 고정하고 숫자만 입력되게 해줘

실무 팁단위를 플레이스홀더로 쓰면 값을 적는 순간 사라져서 "만 원인지 원인지" 헷갈립니다. 서버로 보내는 값에는 접미를 포함하지 않는다는 점을 개발자와 맞추세요. 화면 읽기 도구는 접미를 읽지 않을 수 있으니 라벨에도 단위를 적어두면 안전합니다.

칸과 버튼이 한 덩어리로 붙어 있습니다

03

인풋 그룹 Input group

입력 칸과 버튼·아이콘·단위를 한 덩어리로 붙여둔 부품입니다. 접두·접미가 "글자 붙이기"라면 인풋 그룹은 동작하는 부품(버튼)까지 붙이는 것입니다.

언제 쓰나쿠폰 입력+적용, 이메일+중복 확인, 링크+복사처럼 입력과 바로 이어지는 동작이 있을 때.

AI에게 이렇게쿠폰 입력 칸 오른쪽에 "적용" 버튼을 붙인 인풋 그룹으로 만들어줘

실무 팁붙인 버튼이 비어 있을 때도 눌리면 "빈 값"이라는 안내가 나가야 합니다. 좁은 폰 화면에서는 한 줄에 억지로 붙이지 말고 칸 아래로 내리는 편이 낫습니다. 엔터 키로도 같은 동작이 되는지 꼭 확인하세요.

"대"를 입력해 보세요. 후보가 걸러집니다

04

검색 가능한 셀렉트 Searchable select · Combobox

목록에서 고르되, 글자를 입력해 후보를 줄일 수 있는 선택 칸입니다. 일반 드롭다운은 눈으로 훑어야 하지만 이쪽은 타이핑으로 찾습니다. 콤보박스라고도 부릅니다.

언제 쓰나국가, 은행, 학교, 직업처럼 항목이 수십 개 이상이라 스크롤로 찾기 힘들 때.

AI에게 이렇게은행 선택을 입력하면 후보가 걸러지는 검색 가능한 셀렉트(콤보박스)로 바꿔줘

실무 팁일치하는 항목이 없을 때의 문구와, 목록에 없는 값을 적어도 되는지를 먼저 정하세요. 자동완성이 목록 밖 값도 받는 건지 혼동해서 잘못된 값이 저장되는 일이 잦습니다. 방향키와 엔터로 고를 수 있어야 하고, 항목이 7개 이하라면 그냥 라디오가 더 빠릅니다.

관심 분야 (여러 개)

눌러서 여러 개를 켜고 끄세요

05

다중 선택 칩 Multi-select chips

항목을 여러 개 고를 수 있는 선택 부품입니다. 칩을 눌러 켜는 형태, 목록에 체크 표시가 붙는 형태, 고른 값이 칩으로 쌓이는 형태가 있습니다. 하나만 고르는 셀렉트와 달리 고른 값이 모두 보여야 합니다.

언제 쓰나관심 분야, 필터 조건, 받는 사람 지정처럼 중복 선택이 가능한 값.

AI에게 이렇게관심 분야를 최대 3개까지 고르는 멀티 셀렉트 칩으로 만들고 고른 개수를 보여줘

실무 팁최대 개수가 있다면 넘겼을 때 막기만 하지 말고 이유를 말해야 합니다. 선택이 많아지면 칩이 줄줄이 늘어나 화면을 밀어내니 "외 N개"로 접는 규칙도 필요합니다. 켜짐과 꺼짐을 색으로만 구분하면 색약 사용자는 못 보니 체크 표시를 함께 쓰세요.

받을 알림

06

체크박스 그룹 Checkbox group

관련된 체크박스를 하나의 제목 아래 묶은 것입니다. 각각 독립적으로 켜고 끌 수 있고 선택하지 않아도 됩니다. 하나만 고르는 라디오 그룹과 달리 0개~전부 선택이 가능합니다.

언제 쓰나알림 수신 채널, 관심 항목, 옵션 추가처럼 독립적인 선택이 여럿 있을 때.

AI에게 이렇게알림 수신 방법을 제목이 있는 체크박스 그룹으로 만들어줘

실무 팁그룹 제목이 없으면 화면 읽기 도구는 체크박스 이름만 읽어 맥락을 잃습니다. 이 제목은 시각적으로도 <fieldset>과 <legend>로 묶는 게 가장 간단합니다. 글자만 눌리게 두지 말고 라벨 전체를 눌러도 체크되게 하세요.

07

라디오 카드 Selectable card

라디오 버튼을 카드 한 장으로 키운 것입니다. 안에 제목·가격·설명을 담을 수 있고, 카드 전체가 눌리는 영역이 됩니다. 동작은 라디오와 같아서 하나만 선택됩니다.

언제 쓰나요금제, 배송 방법, 결제 방식처럼 항목마다 설명이 붙고 비교가 필요한 단일 선택.

AI에게 이렇게요금제를 라디오 카드로 보여주고 선택된 카드는 테두리와 배경색이 바뀌게 해줘

실무 팁카드 모양이라고 해서 라디오의 키보드 동작(방향키로 이동)을 빼먹으면 접근성이 무너집니다. 선택됨을 테두리 색 하나로만 알리지 말고 체크 아이콘을 같이 쓰세요. 카드 안에 링크나 버튼을 또 넣으면 어디를 눌러야 하는지 충돌합니다.

수량
1
1~5 사이에서 눌러 보세요

08

숫자 증감 입력 Number input (± buttons)

− 와 + 버튼으로 숫자를 한 칸씩 바꾸는 입력 부품입니다. 값이 최소·최대에 닿으면 해당 버튼이 꺼집니다. 단계를 알려주는 스테퍼와 이름이 비슷하지만 값을 입력하는 도구입니다.

언제 쓰나수량, 인원, 박 수처럼 범위가 작고 정수인 값.

AI에게 이렇게수량을 1에서 5까지 고르는 − / + 숫자 증감 입력을 만들고 한계에서는 버튼을 비활성화해줘

실무 팁버튼이 작으면 손가락으로 − 대신 +를 누르는 사고가 생깁니다. 각 버튼은 44pt 이상으로 하고, 가운데 숫자를 직접 입력할 수 있는지 정하세요. 값이 100처럼 커질 수 있다면 증감 버튼보다 직접 입력이 훨씬 빠릅니다.

고르면 바로 미리 보입니다

09

이미지 업로드 미리보기 Image upload preview

고른 사진을 서버에 보내기 전에 작은 썸네일로 먼저 보여주는 부품입니다. 파일 이름만 보이는 일반 파일 첨부와 달리 내가 고른 사진이 맞는지 눈으로 확인하게 합니다.

언제 쓰나프로필 사진, 상품 등록, 후기 사진 첨부처럼 사진이 결과물의 일부일 때.

AI에게 이렇게후기 사진을 선택하면 썸네일 미리보기가 뜨고 우측 위 X 버튼으로 삭제되게 해줘

실무 팁용량 초과, 지원하지 않는 형식, 업로드 실패 상태를 안 그리는 경우가 대부분입니다. 썸네일 안에 진행률과 다시 시도 버튼이 들어갈 자리를 잡아두세요. 삭제 X는 작기 쉬워서 터치 영역을 따로 넓혀야 합니다.

마우스나 손가락으로 그려 보세요

10

서명 패드 Signature pad

손가락이나 펜으로 서명을 직접 그리는 입력 영역입니다. 결과가 글자가 아니라 그림(이미지)으로 저장된다는 점이 다른 입력과 다릅니다. 지우고 다시 쓰는 버튼이 함께 붙습니다.

언제 쓰나전자 계약, 배송 수령 확인, 동의서처럼 본인 확인이 필요한 서류.

AI에게 이렇게계약서 하단에 지우기 버튼이 있는 서명 패드를 넣고 결과를 PNG로 저장해줘

실무 팁서명 영역에서 손가락으로 그리다 화면이 같이 스크롤되는 사고가 빈번합니다. 그리는 동안은 스크롤을 막아야 합니다. 비어 있는 서명을 제출할 수 있는지, 가로 모드에서 크게 쓸 수 있는지도 정해두세요.

배송지
  • 서울 중구 세종대로 110
  • 서울 중구 세종대로 99

11

주소 검색 Address search

주소를 직접 적지 않고 검색해서 고르는 입력 방식입니다. 기본 주소는 검색 결과로 채우고(수정 불가), 동·호수 같은 상세 주소만 직접 입력합니다.

언제 쓰나배송지, 사업장, 가입 정보처럼 우편번호까지 정확해야 하는 주소.

AI에게 이렇게주소 검색 버튼을 누르면 결과를 고를 수 있게 하고, 고른 뒤에 상세 주소 칸이 활성화되게 해줘

실무 팁검색 결과가 없는 건물, 해외 주소, 도서산간 추가 배송비를 처리하지 않으면 주문 직전에 막힙니다. 검색 창이 새 창으로 뜨는 외부 서비스를 쓰면 모바일에서 뒤로 가기 때 입력한 내용이 날아가기 쉽습니다. 고른 뒤 상세 주소 칸으로 포커스를 자동으로 옮기세요.

단순화한 예시. 눌러 보세요

12

캡차 CAPTCHA

사람이 맞는지 확인해서 자동 프로그램(봇)의 가입·도배를 막는 장치입니다. 체크박스 한 번, 그림 고르기, 퍼즐 맞추기 등 여러 방식이 있습니다. 보이지 않게 점수만 매기는 방식도 있습니다.

언제 쓰나회원가입, 로그인 실패 반복, 대량 문의 폼처럼 봇 공격이 오는 입구.

AI에게 이렇게회원가입 폼 제출 직전에 "로봇이 아닙니다" 체크박스 캡차를 넣어줘

실무 팁그림을 고르는 캡차는 시각장애 사용자를 막아버리니 음성 대체나 다른 확인 방법이 반드시 필요합니다. 모든 사람에게 처음부터 걸지 말고 수상할 때만 걸면 가입 이탈이 줄어듭니다. 실패했을 때 입력한 폼 내용이 지워지지 않아야 합니다.

  • 8자 이상
  • 숫자 포함
  • 특수문자 포함

13

비밀번호 규칙 체크리스트 Password rules checklist

입력하는 동안 비밀번호 조건을 항목별로 충족했는지 하나씩 체크해 보여주는 목록입니다. 막대 하나로 세기만 알려주는 강도 표시기와 달리 무엇이 부족한지 구체적으로 알려줍니다.

언제 쓰나회원가입, 비밀번호 변경처럼 조건이 정해진 비밀번호 설정 화면.

AI에게 이렇게비밀번호 입력 아래에 8자 이상·숫자·특수문자 규칙 체크리스트를 실시간으로 표시해줘

실무 팁규칙을 제출한 뒤에야 알려주면 사용자는 세 번 틀립니다. 입력 전부터 보이게 두고, 만족하면 색뿐 아니라 ○에서 ●로 모양도 바꿔야 합니다. 조건을 빡빡하게 걸수록 약한 비밀번호를 돌려 쓰게 되니, 길이 중심으로 단순하게 가는 것이 좋습니다.

14

폼 섹션·필드셋 Form section · Fieldset

관련된 입력 칸을 제목 아래 한 덩어리로 묶은 것입니다. HTML에서는 fieldset과 legend라는 태그가 이 역할을 합니다. 긴 폼을 "배송 / 결제"처럼 의미 단위로 나눕니다.

언제 쓰나칸이 8개를 넘는 폼, 성격이 다른 입력(개인정보·결제)이 섞인 화면.

AI에게 이렇게주문 폼을 배송 정보와 결제 정보 두 개의 폼 섹션(fieldset)으로 나눠줘

실무 팁섹션을 나누는 목적은 예쁜 구분선이 아니라 "다음에 무엇을 묻는지" 예고하는 것입니다. 섹션 제목이 "기본 정보" 같은 빈말이면 의미가 없습니다. 섹션마다 따로 접거나 저장하는 구조라면 각 섹션이 독립적으로 오류를 가질 수 있게 설계하세요.

15

제출 후 요약 Review step

제출 버튼을 누르기 직전에 입력한 내용을 한 화면에 모아 다시 보여주는 단계입니다. 항목마다 수정 링크가 붙어 틀린 곳으로 바로 돌아갈 수 있습니다. 확인 단계, 리뷰 스텝이라고도 합니다.

언제 쓰나결제, 신청서, 예약처럼 한 번 제출하면 되돌리기 어려운 여러 단계의 폼.

AI에게 이렇게마지막 단계에 입력 내용을 요약해서 보여주는 Review step을 만들고 항목마다 수정 링크를 달아줘

위쪽 라벨 vs 왼쪽 라벨 Top label · Left label

라벨을 칸 위에 두느냐 왼쪽에 두느냐의 차이입니다. 위쪽은 세로로 훑기 쉽고 폭이 좁아도 되며, 왼쪽은 표처럼 정리돼 보이지만 라벨 폭이 길면 칸이 줄어듭니다.

눌러 보세요. 처리 중엔 다시 눌러지지 않습니다

중복 제출 방지 Double-submit prevention

제출 버튼을 한 번 누르면 처리가 끝날 때까지 다시 눌러지지 않게 막는 것입니다. 안 막으면 두 번 눌러서 주문이나 결제가 두 번 들어갈 수 있습니다.

언제 쓰나결제, 주문, 송금, 글 등록처럼 두 번 실행되면 문제가 되는 모든 제출.

AI에게 이렇게결제하기 버튼은 누르면 로딩 표시와 함께 비활성화되어 중복 제출이 안 되게 해줘

실무 팁버튼만 막으면 엔터 키나 새로고침으로 다시 제출됩니다. 서버도 같은 요청을 두 번 받지 않게 설계해야 진짜 방지입니다. 실패했을 때 버튼이 영원히 잠겨 있는 버그를 가장 많이 봅니다. 꼭 다시 풀리는지 확인하세요.

약관 전체 동의 Agree to all (Terms consent)

약관 여러 개를 한 번에 체크하는 "전체 동의" 체크박스가 맨 위에 있는 부품입니다. 하위 항목을 모두 체크하면 전체 동의도 켜지고, 하나라도 풀면 꺼집니다. 부모-자식 체크박스 구조입니다.

언제 쓰나회원가입, 서비스 신청처럼 약관과 선택 동의가 여러 개인 화면.

AI에게 이렇게가입 화면 상단에 "전체 동의" 체크박스를 두고 하위 약관과 양방향으로 연동해줘

실무 팁필수와 선택을 시각적으로 구분하지 않으면 마케팅 동의까지 한꺼번에 받았다고 지적받을 수 있습니다. 전체 동의가 선택 항목까지 포함한다는 걸 문구로 알리세요. 약관 내용을 볼 수 있는 링크와 하위 항목 일부만 체크된 상태가 어떻게 보이는지도 정해야 합니다.
