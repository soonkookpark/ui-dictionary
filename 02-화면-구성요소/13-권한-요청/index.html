01

알림 권한 Notification

앱이 화면 밖에서도 푸시 알림을 보내도 되는지 묻는 권한. 아이폰은 첫 실행 때 한 번 묻고, 안드로이드 13 이상도 같은 방식으로 묻습니다. 푸시 알림 권한이라고도 합니다.

언제 쓰나배송 상태, 채팅 새 메시지, 예약 확인처럼 앱을 열어 두지 않아도 알려야 하는 서비스.

AI에게 이렇게알림 권한을 첫 실행 때 바로 묻지 말고 주문을 마친 뒤 사전 안내 화면을 보여준 다음에 요청해줘

20년차 메모첫 실행 때 아무 설명 없이 묻는 경우가 가장 흔한 실수입니다. 사용자는 "허용 안 함"을 누르고, 안 하면 나중에 다시 물을 수 없습니다. 가치를 느낀 순간(주문 직후)에 요청하세요. 안드로이드와 아이폰은 묻는 시점과 기본값이 달라 플랫폼별로 따로 설계해야 합니다.

02

위치 권한 Location

내 위치를 앱이 읽어도 되는지 묻는 권한. 항상, 앱 사용 중에만, 이번만처럼 허용 범위를 고를 수 있어서 다른 권한보다 선택지가 많습니다.

언제 쓰나지도, 배달, 근처 매장 찾기, 택시 호출 같은 위치가 있어야 되는 기능.

AI에게 이렇게근처 매장 찾기를 누를 때 위치 권한을 요청하고, 거절하면 주소를 직접 입력하는 화면으로 넘어가게 해줘

20년차 메모"항상 허용"을 요구하면 대부분 거부당하고 심사에서 이유를 묻습니다. 정말 필요한 기능이 아니면 "앱 사용 중"만 요청하세요. 거절해도 직접 주소를 입력하는 대안이 있어야 앱이 멈추지 않습니다.

03

카메라 권한 Camera

앱이 카메라를 켜도 되는지 묻는 권한. 사진 찍기, QR 스캔, 영상 통화처럼 카메라 화면이 필요한 순간에 요청합니다. 마이크 권한도 같은 방식입니다.

언제 쓰나프로필 사진 촬영, 영수증·서류 스캔, QR 코드 읽기.

AI에게 이렇게사진 찍기 버튼을 처음 눌렀을 때 카메라 권한을 요청하고 허용되면 바로 카메라 화면을 열어줘

20년차 메모카메라 화면이 열려 있는 상태에서 처음 묻는 건 어색합니다. 버튼을 누르는 그 순간 물으세요. 허용 후 카메라가 켜지기까지 빈 검은 화면이 보이지 않게 로딩을 넣고, 갤러리에서 고르는 대안도 두세요.

배송 소식을 알려드릴까요?출발과 도착 때만 보내고 광고는 보내지 않아요나중에 할게요

04

미리 안내 Pre-permission

시스템 창을 띄우기 전에 우리 앱의 화면으로 이유를 먼저 설명하는 단계. 사전 안내 화면(priming screen)이라고도 합니다. 여기서 "나중에"를 눌러도 시스템 창은 아직 안 썼으므로 다시 물을 수 있습니다.

언제 쓰나시스템 권한 창을 띄우기 직전. 이유를 설명해야 허용률이 달라지는 알림·위치 권한.

AI에게 이렇게알림 권한을 요청하기 전에 이유를 설명하는 화면을 먼저 보여주고 알림 켜기를 누르면 시스템 창을 띄워줘

20년차 메모사전 안내에서 "켜기"를 눌러야만 시스템 창을 띄우는 순서를 꼭 지키세요. 시스템 창이 한 번 거절되면 되돌리기 어렵기 때문입니다. 안내 글은 "허용해주세요"가 아니라 사용자가 얻는 이익으로 쓰세요.

알림을 보내도 될까요?앱이 보내는 모든 알림

05

시스템 모달 System dialog

기기(iOS, 안드로이드)가 직접 띄우는 권한 창. 모양과 글을 앱이 마음대로 바꿀 수 없고 문구의 일부만 앱이 정합니다. 눌러 보면 앱 화면 위로 떠서 선택 전까지 뒤의 화면을 못 쓰게 막는 모달입니다.

언제 쓰나앱이 권한을 처음 요청하는 순간. 한 번 거절하면 같은 창을 다시 쓸 수 없는 경우가 많습니다.

AI에게 이렇게권한 요청 직전에 사전 안내를 거쳐 시스템 권한 창을 띄우고, 사용자가 선택한 결과에 따라 화면을 나눠줘

20년차 메모시스템 창의 설명 문구(Info.plist의 용도 문구)는 개발자가 쓰는데, 기본 문구 그대로 두거나 영어로 남아 있는 경우가 많습니다. 디자이너가 직접 챙기세요. 창이 뜬 동안에는 앱 화면에 이벤트가 일어나지 않아 화면이 멈춘 것처럼 보일 수 있습니다.

06

다시 묻기 Re-prompt

한 번 거절당한 권한을 나중에 다시 부탁하는 것. 시스템 창은 거절 후 다시 띄우지 못하는 경우가 많아서, 우리 앱의 화면으로 "켜볼까요?"라고 다시 묻고 설정으로 보내는 식이 됩니다.

언제 쓰나사용자가 거절했는데, 그 권한이 있어야 얻는 가치를 느낄 만한 시점이 왔을 때.

AI에게 이렇게알림을 거절한 사용자가 주문을 마쳤을 때 한 번만 배너로 알림을 켜면 배송 소식을 받을 수 있다고 다시 안내해줘

20년차 메모너무 자주 다시 물으면 사용자가 앱을 지웁니다. 횟수(예: 두 번까지)와 간격(며칠)을 정해 두세요. 이번에도 거절한다면 더 이상 묻지 않는다는 규칙도 필요합니다. 안드로이드는 두 번 거절하면 시스템 창이 아예 안 뜹니다.

알림이 꺼져 있어요설정 › 앱 › 알림에서 켤 수 있어요
알림 허용

07

설정으로 보내기 Go to settings

시스템 창으로 더 이상 물을 수 없을 때, 기기의 설정 화면으로 직접 이동시키는 버튼. 사용자가 거기서 권한을 직접 켭니다. 앱이 허용 상태를 바꿀 수는 없습니다.

언제 쓰나한 번 거절된 뒤 사용자가 "그래도 쓰고 싶다"고 했을 때.

AI에게 이렇게알림이 꺼져 있으면 안내 문구와 함께 설정 열기 버튼을 보여주고 누르면 기기의 앱 설정 화면으로 이동하게 해줘

20년차 메모버튼 이름이 "설정"뿐이면 어디로 가는지 모릅니다. "설정 열기"와 함께 켜는 경로(설정 › 앱 › 알림)를 적어 주세요. 사용자가 설정에서 켜고 돌아왔을 때 앱이 다시 확인해 화면을 갱신하는지 개발자와 점검하세요.

허용한 사진 5장만 앱이 볼 수 있어요

08

일부만 허용 Limited access

모든 것이 아니라 일부만 앱에 허용하는 선택지. 아이폰·안드로이드의 사진 접근에서 "선택한 사진만"이 대표적이고, 위치의 "대략적인 위치"도 같은 계열입니다.

언제 쓰나사진첩, 연락처처럼 앱이 전부를 봐야 할 필요가 없는 권한.

AI에게 이렇게사진 접근이 일부 허용이면 허용된 사진만 보여주고 아래에 사진 더 선택 버튼을 보여줘

20년차 메모일부만 허용된 상태를 "전체 허용"으로 가정하고 만들면 사진이 안 보이는 버그가 납니다. 이 상태도 시안에 그려야 합니다. 더 고르는 버튼을 두고, 허용 범위가 얼마인지 사용자에게 알려 주세요.

카메라를 쓸 수 없어요권한이 꺼져 있어서 사진을 찍을 수 없어요

09

거절 뒤 화면 Denied state

권한을 거절한 사용자가 그 기능 화면에 들어왔을 때 보여주는 화면. 빈 검은 화면 대신 이유를 설명하고 해결 방법과 대안을 줍니다. 빈 상태(empty state)의 한 종류입니다.

언제 쓰나카메라·위치·알림을 거절한 뒤 그 기능을 다시 열었을 때.

AI에게 이렇게카메라 권한이 거절된 상태에서는 빈 화면 대신 안내 문구와 설정에서 켜기 버튼, 앨범에서 고르기 대안 버튼을 보여줘

20년차 메모이 화면을 안 그리면 사용자는 검은 화면만 보고 앱이 고장났다고 생각합니다. 거절 화면은 시안에서 가장 자주 빠지는 화면입니다. 비난하는 어조보다 "이렇게 하면 쓸 수 있어요"로 쓰고, 설정으로 가는 버튼과 대안 하나를 꼭 두세요.

10

사용 중에만 허용 While using

앱이 화면에 떠 있는 동안에만 권한을 쓰게 하는 허용 범위. "항상"과 달리 앱을 닫으면 위치를 읽을 수 없습니다.

언제 쓰나위치·마이크·카메라처럼 늘 켜 둘 필요가 없는 권한.

AI에게 이렇게위치 권한은 앱 사용 중에만 요청하고 항상 허용은 요청하지 말아줘

20년차 메모"이번만 허용"을 고른 사용자는 다음 방문 때 다시 물어야 하므로 거절이 아닌 상태로 취급하세요. 이 허용 범위 이름이 안드로이드와 아이폰에서 조금 달라 문구를 맞추는 일이 필요합니다.

11

정확한 위치 vs 대략적인 위치 Precise vs Approximate

위치를 어느 정밀도로 줄지 고르는 선택. 정확한 위치는 건물 단위, 대략적인 위치는 몇 킬로미터 반경 정도입니다. 둘을 가르는 기준은 앱이 위치를 얼마나 세밀하게 알아야 하느냐입니다.

이렇게 구분건물 단위 위치가 필요한 기능(배달)이면 정확한 위치, 동네 정도면 충분한 기능(날씨, 지역 소식)이면 대략적인 위치.

AI에게 이렇게날씨 화면은 대략적인 위치만 요청하고, 배달 화면은 정확한 위치를 요청해줘

20년차 메모정확한 위치만 가정하고 만들면 사용자가 대략적인 위치를 골랐을 때 지도 핀이 엉뚱한 곳에 찍힙니다. 대략적인 위치로 와도 앱이 돌아가는지 확인하세요.

12

권한 상태 Permission states

권한이 지금 어떤 상태인지를 가르는 이름. 앱은 "허용/거절" 둘이 아니라 최소 세 가지(아직 안 물음, 허용, 거부)로 나눠 생각해야 합니다.

언제 쓰나권한 화면을 설계하거나 개발자와 "이 경우엔 어떻게 보이냐"를 정리할 때.

AI에게 이렇게권한 상태를 미결정, 허용, 거부, 제한 네 가지로 나눠서 상태별 화면을 정리해줘

20년차 메모디자이너가 허용 상태만 그려 오고 나머지는 개발자가 알아서 처리하는 일이 흔합니다. 상태 표를 만들어 상태마다 화면을 하나씩 그려 주세요. 사용자는 설정에서 언제든 바꿀 수 있어서 앱을 다시 열 때마다 상태를 확인해야 합니다.
