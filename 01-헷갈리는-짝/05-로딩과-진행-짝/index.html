01

스피너 vs 스켈레톤 Spinner vs Skeleton

'처리 중'이라는 사실만 알려 주면 스피너, 곧 나타날 화면의 뼈대를 회색 덩어리로 미리 그려 놓으면 스켈레톤입니다.

이렇게 구분버튼을 눌러 짧게 처리할 때는 스피너, 피드·목록처럼 화면 모양이 정해진 곳을 처음 불러올 때는 스켈레톤.

AI에게 이렇게목록은 불러오는 동안 카드 모양 스켈레톤을 보여주고, 저장 버튼에는 작은 스피너를 넣어줘

실무 팁스켈레톤 모양이 실제 내용과 다르면 내용이 뜰 때 화면이 덜컥 움직입니다. 스켈레톤을 깐 채로 실패하면 영원히 회색이 남는 화면이 자주 나오니 오류 상태를 꼭 같이 그리세요. 1초 안에 끝나는 일에 스켈레톤을 쓰면 오히려 깜빡임처럼 보입니다.

02

스켈레톤 vs 플레이스홀더 Skeleton vs Placeholder

빈자리를 채운다는 점은 같지만 스켈레톤은 곧 올 내용의 모양으로 반짝이며 기다림을 알리고, 플레이스홀더는 가만히 있는 대체물(기본 그림, 샘플 글)로 자리를 지킵니다.

이렇게 구분서버에서 가져오는 중이라는 신호가 필요하면 스켈레톤, 내용이 아예 없거나 비어 있어서 대신 보여주는 그림이면 플레이스홀더입니다. 입력창 안의 회색 안내 글도 플레이스홀더라고 부르는 점에 주의하세요.

AI에게 이렇게프로필 사진이 없으면 사람 모양 플레이스홀더를 보여주고, 목록을 불러오는 동안은 스켈레톤을 보여줘

실무 팁개발 문서에서 placeholder 는 입력창 안내 글을 가리키는 일이 많아, 그림 자리를 말할 때는 "기본 이미지"라고 풀어 쓰는 편이 안전합니다. 스켈레톤은 반짝임이 계속 돌면 전정기관이 예민한 사용자에게 부담이니 모션 줄이기 설정에서는 멈추게 하세요. 둘을 섞어 불러오는 중에도 기본 이미지를 보여주면 아직 로딩 중인지 원래 없는 건지 구분이 안 됩니다.

03

스플래시 vs 로딩 화면 Splash vs Loading screen

앱을 열 때 보이는 첫 화면이라는 점은 같습니다. 스플래시는 앱이 켜지는 짧은 순간 브랜드 로고를 보여주는 화면이고, 로딩 화면은 데이터를 기다리는 동안 진행 상태를 알려 주는 화면입니다.

이렇게 구분앱을 켜는 첫 1~2초에 로고만 있으면 스플래시, 켜진 뒤 목록·결제 정보를 가져오며 진행을 보여 주면 로딩 화면입니다.

AI에게 이렇게앱 실행 때 로고만 보이는 스플래시를 짧게 보여주고, 데이터를 가져오는 동안은 진행 바가 있는 로딩 화면으로 이어줘

실무 팁스플래시를 일부러 길게 늘리면 앱이 느리다는 인상만 남습니다. 앱이 준비되는 즉시 넘어가는 것이 원칙입니다. 안드로이드 12부터는 시스템이 스플래시를 먼저 보여주기 때문에 별도로 만든 스플래시가 두 번 뜨는 사고가 많으니 개발자와 확인하세요. 로딩 화면에는 실패했을 때 다시 시도할 길을 꼭 두세요.

04

지연 로딩 Lazy loading

처음부터 전부 불러오지 않고, 화면에 보이기 직전에 필요한 만큼만 불러오는 방식입니다. 무한 스크롤과 이미지 목록에서 속도를 지키는 기본기입니다.

언제 쓰나긴 피드, 이미지가 많은 페이지, 아래쪽 비디오처럼 처음 화면에 없는 것들.

AI에게 이렇게이미지는 화면에 가까워질 때만 불러오도록 지연 로딩을 적용해줘

실무 팁이미지 자리를 미리 잡아 두지 않으면 지연 로딩이 오히려 화면을 덜컥거리게 합니다. 비율을 고정한 자리표시(스켈레톤)와 함께 쓰세요.

05

진행 바 vs 단계 표시 Progress vs Steps

연속된 양이 채워지며 '몇 퍼센트'를 보여주면 진행 바, 정해진 칸으로 나뉘어 '3단계 중 2단계'를 보여주면 단계 표시(스텝)입니다.

이렇게 구분업로드·설치처럼 연속적으로 차오르면 진행 바, 가입·결제처럼 화면이 나뉘어 있으면 단계 표시.

AI에게 이렇게파일 업로드에는 퍼센트가 있는 진행 바를, 결제 화면 위에는 3단계 스텝 표시를 넣어줘

실무 팁단계마다 입력량이 다른데 진행 바를 3분의 1씩 채우면 사용자가 속았다고 느낍니다. 단계 표시는 이름까지 써야 의미가 있고, 바로 앞 단계로 돌아가 고칠 수 있어야 합니다. 로딩과 입력 단계를 같은 막대 모양으로 섞어 쓰지 마세요.

06

온보딩 vs 튜토리얼 Onboarding vs Tutorial

온보딩은 처음 오는 사용자를 맞아 가치와 준비를 알려 주는 전체 과정이고, 튜토리얼은 그중 실제 화면 위에서 사용법을 짚어 가르치는 부분입니다. 온보딩이 더 넓은 말입니다.

이렇게 구분가입 직후 환영·권한 요청·관심사 고르기까지 흐름이면 온보딩, 버튼을 하나씩 가리키며 쓰는 법을 알려 주면 튜토리얼(코치마크)입니다.

AI에게 이렇게첫 실행 시 3장짜리 환영 슬라이드를 보여주고, 홈 화면에서는 주요 버튼을 하나씩 짚는 튜토리얼을 건너뛸 수 있게 넣어줘

실무 팁온보딩은 길수록 이탈이 늘어서, 모든 설명을 첫 화면에 몰지 말고 그 기능을 처음 쓸 때 보여주는 편이 낫습니다. 건너뛰기 버튼이 없거나 다시 볼 방법이 없는 튜토리얼이 가장 흔한 실수입니다. 실제 서비스 화면에 가려 읽을 시간이 없다면 자동으로 넘어가지 않게 하세요.
