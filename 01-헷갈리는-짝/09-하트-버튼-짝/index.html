01

좋아요 vs 찜 Like vs Wishlist

누른 사람의 반응이 숫자로 남에게 보이면 좋아요, 내 목록에 조용히 담기는 것이 찜입니다. 같은 하트를 쓰는 서비스가 많아 더 헷갈립니다.

이렇게 구분게시글·영상에 반응을 남기면 좋아요, 상품·숙소를 나중에 보려고 담으면 찜.

AI에게 이렇게상품 카드 오른쪽 위에는 하트 모양 찜 버튼을 달고 누르면 내 찜 목록에 저장되게 해줘

실무 팁서비스 안에 '좋아요'와 '찜'이 둘 다 하트면 사용자는 어디에 쌓이는지 모릅니다. 찜은 어느 화면에서 모아 보는지를 누르는 순간 토스트로 알려 주세요('찜 목록에 담았어요 · 보기'). 하트 하나에 두 뜻을 넣으려면 서비스의 목적부터 정해야 합니다.

02

찜 vs 장바구니 Wishlist vs Cart

'나중에 볼게'라는 마음이면 찜, '이걸 살 거야'라는 결정에 가까우면 장바구니입니다. 장바구니에는 수량과 총액이 붙지만 찜에는 붙지 않습니다.

이렇게 구분사고 싶은지 아직 모르면 찜, 수량·옵션을 정해 결제를 준비하면 장바구니.

AI에게 이렇게상품 상세에는 찜 하트 버튼과 장바구니 담기 버튼을 따로 두고, 장바구니 아이콘에는 담은 개수 배지를 달아줘

실무 팁찜한 상품을 장바구니로 쉽게 옮기는 길이 없으면 두 기능이 따로 노는 죽은 목록이 됩니다. 찜 목록에서 바로 담기 버튼을 주세요. 품절이 된 찜 상품은 눈에 띄게 표시해야 헛걸음을 막습니다.

03

북마크 vs 좋아요 Bookmark vs Like

내가 다시 찾아보려고 모아두는 건 북마크(저장), 글쓴이와 다른 사람에게 반응을 드러내는 건 좋아요입니다.

이렇게 구분읽을거리·레시피를 모아 두려면 북마크, 응원하거나 공감한다는 표시를 남기려면 좋아요.

AI에게 이렇게글 아래에 북마크 저장 아이콘과 하트 좋아요를 따로 두고, 북마크한 글은 내 프로필의 저장됨 탭에서 모아 보게 해줘

실무 팁북마크한 사실이 상대에게 알려지지 않는다는 점을 사용자에게 알려 주면 마음 놓고 씁니다. 저장함이 비었을 때(빈 상태) 안내와, 지운 글이 저장함에서 어떻게 보이는지도 정해야 합니다.

04

팔로우 vs 알림 설정 Follow vs Notify

팔로우는 그 사람의 글을 내 피드에서 받아 보겠다는 구독이고, 알림 설정은 새 글이 올라올 때 폰으로 알림까지 받겠다는 별도 선택입니다.

이렇게 구분소식을 가끔 훑어보려면 팔로우만, 놓치지 않고 받으려면 팔로우한 뒤 알림 설정.

AI에게 이렇게프로필에 팔로우 버튼을 두고, 팔로잉 상태에서만 새 글 알림 종 아이콘이 보이게 해줘

실무 팁알림을 팔로우와 함께 자동으로 켜 버리면 알림이 폭주하고 곧바로 앱 알림을 전부 끄게 됩니다. 팔로우와 알림은 분리하세요. 팔로우 버튼이 '팔로잉'으로 바뀐 뒤 다시 눌렀을 때 바로 취소되는지 확인 창이 뜨는지도 정해야 합니다.

05

공유 vs 링크 복사 Share vs Copy link

공유는 카카오톡·메시지 같은 보낼 앱 목록을 띄워 바로 전달하는 것이고, 링크 복사는 주소만 복사해 두고 사용자가 직접 붙여넣는 것입니다.

이렇게 구분누군가에게 바로 보내려면 공유, 원하는 곳에 직접 붙이려면 링크 복사.

AI에게 이렇게공유 버튼은 기기 공유 시트를 열고, 링크 복사 버튼을 누르면 복사했어요 토스트를 띄워줘

실무 팁링크를 복사했는데 아무 반응이 없으면 사용자는 복사가 됐는지 모릅니다. 토스트 같은 작은 확인이 꼭 필요합니다. 웹에서는 기기 공유 시트가 지원되지 않는 브라우저가 있어 링크 복사를 기본으로 깔아 두는 편이 안전합니다.

06

별점 vs 리뷰 Rating vs Review

별을 눌러 점수를 매기는 건 별점, 사용 경험을 글이나 사진으로 쓰는 건 리뷰입니다. 별점이 한눈에 읽히고 리뷰는 이유를 알려줍니다.

이렇게 구분빠르게 평가를 모으려면 별점, 이유와 구체적인 사용 후기를 모으려면 리뷰.

AI에게 이렇게상품 평가는 눌러서 고르는 5점 별점을 먼저 받고, 이어서 선택 사항으로 리뷰 글을 쓰게 해줘

실무 팁별 버튼이 작아 손가락으로 4점과 5점이 잘못 눌리는 일이 많으니 별 하나를 44pt 이상으로 잡으세요. 별점이 있는 곳에는 '평균 4.5 · 리뷰 120개'처럼 개수를 같이 보여줘야 신뢰가 갑니다. 반 개 별을 허용할지 개발과 정해야 합니다.

최근 본 vs 찜 목록 Recent vs Wishlist

내가 아무것도 안 해도 본 순서대로 자동으로 쌓이는 건 최근 본, 내가 직접 하트를 눌러 고른 것만 담기는 건 찜 목록입니다.

이렇게 구분'아까 본 그거'를 찾으려면 최근 본, 계속 갖고 싶은 것을 모아 두려면 찜 목록.

AI에게 이렇게상품 목록 화면에 자동으로 기록되는 최근 본 상품과, 하트를 눌러 담는 찜 목록을 따로 만들어줘

실무 팁최근 본 목록은 개인의 열람 기록이라 지우기와 '기록 끄기' 버튼이 있어야 합니다. 자동 목록은 길이가 끝없이 늘어나니 최대 개수(예: 50개)와 오래된 항목 정리 규칙을 정하세요. 찜은 사용자가 만든 데이터라 서버 저장과 기기 간 동기화가 필요합니다.

08

좋아요 vs 리액션 Like vs Reaction

눌러서 켜고 끄는 한 가지 반응이면 좋아요, 누르고 있거나 올리면 여러 감정(웃음·놀람·슬픔 등)이 나와 골라서 표현하면 리액션입니다.

이렇게 구분단순하고 빠른 반응이면 좋아요, 감정이 다양한 대화·커뮤니티에는 리액션.

AI에게 이렇게공감 버튼을 길게 누르거나 마우스를 올리면 여러 이모지 리액션 중 고르는 트레이가 열리게 해줘

실무 팁리액션 종류가 많아지면 고르는 데 시간이 걸려서 오히려 누르는 사람이 줄어듭니다. 대여섯 개 안으로 두세요. 모바일은 마우스 올리기가 없어서 길게 누르기로 대체해야 하고, 짧게 눌렀을 때 기본 반응이 무엇인지도 정해야 합니다. 이모지는 기기마다 모양이 달라 색 외 의미 전달이 흔들릴 수 있습니다.

09

저장 vs 다운로드 Save vs Download

서비스 안의 내 보관함에 담아 두는 건 저장, 파일 형태로 내 폰·컴퓨터에 내려받는 건 다운로드입니다. 저장은 인터넷이 있어야 볼 수 있지만 다운로드는 파일이 내 기기에 남습니다.

이렇게 구분나중에 앱에서 다시 보려면 저장, 오프라인이나 다른 앱에서 쓰려면 다운로드.

AI에게 이렇게게시물에는 앱 보관함에 담는 저장 북마크를, 문서 파일에는 기기로 받는 다운로드 버튼을 달아줘

실무 팁영어 'Save'를 '저장'이라 번역하면 다운로드의 뜻으로도 읽혀 혼란이 생깁니다. 사진 저장처럼 기기로 받는 동작은 '다운로드'나 '앨범에 저장'처럼 장소를 문구에 넣으세요. 다운로드는 진행 중·완료·실패와 파일 위치 안내까지 필요합니다.

누르면 동그라미 퍼짐

10

마이크로인터랙션 Microinteraction

버튼 하나를 누를 때 생기는 아주 작은 반응입니다. 하트가 톡 커지거나 동그라미가 퍼지는 효과처럼 '눌렸다'는 사실을 눈에 확실히 보여줍니다.

언제 쓰나좋아요·찜·저장처럼 누른 결과가 숫자나 색 말고는 안 보이는 작은 버튼.

AI에게 이렇게하트를 누르면 0.3초 동안 커졌다 돌아오는 마이크로인터랙션과 퍼지는 원 효과를 넣어줘

실무 팁효과가 0.5초를 넘기면 누르는 사람을 기다리게 해서 오히려 느립니다. 움직임을 줄이는 설정을 켠 사용자(prefers-reduced-motion)에게는 효과를 꺼 주세요.

사진을 두 번 눌러 보세요

11

더블 탭 좋아요 Double tap to like

사진을 두 번 연달아 두드리면 좋아요가 눌리는 동작입니다. 인스타그램이 널리 퍼뜨렸습니다.

언제 쓰나사진·영상이 화면을 크게 차지하는 피드.

AI에게 이렇게게시물 사진을 두 번 누르면 가운데에 큰 하트가 나타나며 좋아요가 되게 해줘

실무 팁숨은 제스처라 처음 쓰는 사람은 모릅니다. 반드시 눈에 보이는 하트 버튼도 함께 두세요. 이미 누른 상태에서 다시 더블 탭 하면 취소가 아니라 그대로 유지하는 게 관례입니다.

아직 찜한 상품이 없어요마음에 드는 상품에 하트를 눌러 보세요

12

빈 상태 Empty state

목록에 아직 아무것도 없을 때 보여주는 화면입니다. 그냥 빈 흰 화면으로 두지 않고, 이유와 다음 행동을 알려 줍니다.

언제 쓰나찜 목록·저장함·알림함·검색 결과 없음처럼 처음엔 항상 비어 있는 화면.

AI에게 이렇게찜 목록이 비어 있을 때 안내 문구와 상품 둘러보기 버튼이 있는 빈 상태 화면을 보여줘

실무 팁하트 관련 기능은 처음엔 모두 비어 있으니 사용자가 가장 먼저 보는 화면이 빈 상태입니다. '없습니다'로 끝내지 말고 어떻게 채우는지 알려 주세요. 오류로 비어 보이는 것과 진짜 비어 있는 것을 구분해 다르게 보여주는 것도 중요합니다.
