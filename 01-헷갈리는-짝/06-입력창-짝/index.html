01

안내 문구 vs 오류 문구 Helper vs Error text

입력 전에 규칙을 미리 알려주는 회색 글은 안내 문구, 잘못 입력한 뒤에 무엇이 틀렸는지 알려주는 빨간 글은 오류 문구입니다.

이렇게 구분'8자 이상'처럼 규칙은 안내 문구, '8자 이상이어야 해요'처럼 어긴 뒤의 지적은 오류 문구.

AI에게 이렇게입력칸 아래에 회색 안내 문구를 두고, 형식이 틀리면 칸 테두리와 문구를 빨간 오류 문구로 바꿔줘

20년차 메모오류 문구를 '잘못된 입력입니다'로 쓰면 아무 도움이 안 됩니다. 무엇이 어떻게 틀렸고 어떻게 고치는지를 말하세요. 색만 빨강으로 바꾸면 색약 사용자가 놓치니 아이콘이나 글자로도 알리고, 입력하는 도중이 아니라 칸을 벗어난 뒤에 보여주세요.

02

한 줄 입력 vs 여러 줄 입력 Input vs Textarea

한 줄짜리 짧은 답이면 인풋(한 줄 입력), 문단처럼 길고 줄바꿈이 필요하면 텍스트에어리어(여러 줄 입력)입니다.

이렇게 구분이름·이메일·제목처럼 짧은 값이면 한 줄, 후기·문의·자기소개처럼 길게 쓰면 여러 줄.

AI에게 이렇게제목은 한 줄 입력으로, 본문은 세 줄 높이에서 시작해 내용이 늘면 자동으로 커지는 여러 줄 입력으로 만들어줘

20년차 메모여러 줄 입력의 처음 높이가 한 줄처럼 작으면 사용자는 길게 써도 되는지 모릅니다. 쓸 분량에 맞는 높이를 주세요. Enter가 제출인지 줄바꿈인지는 채팅과 문서에서 반대라 미리 정해야 합니다. 모바일에서는 키보드가 가리지 않도록 스크롤을 확인하세요.

친 글자를 이어서 완성

03

자동완성 vs 추천 검색어 Autocomplete vs Suggest

내가 친 글자의 뒷부분을 이어서 맞춰 주는 건 자동완성, 아직 아무것도 안 쳤을 때 인기·최근 검색어를 먼저 보여주는 건 추천 검색어입니다.

이렇게 구분'서'를 쳤더니 '서울 맛집'이 나오면 자동완성, 검색창을 누르자마자 오늘의 인기어가 보이면 추천 검색어.

AI에게 이렇게검색창에는 입력하는 글자에 맞춰 이어지는 자동완성을 보여주고, 입력 전에는 최근 검색어와 추천 검색어를 보여줘

20년차 메모자동완성 목록이 열린 상태에서 위아래 방향키와 Enter로 고를 수 있어야 하는데 마우스만 되게 만드는 경우가 많습니다. 추천 검색어는 개인정보나 민감한 검색 기록이 남에게 보일 수 있어 지우기 버튼을 반드시 주세요. 한글은 글자를 조합하는 중에도 목록이 갱신되도록 개발과 확인하세요.

04

비밀번호 vs 인증번호 Password vs OTP

내가 직접 정해 두고 오래 쓰는 비밀 문자열이 비밀번호, 지금 이 순간 문자·앱으로 받은 일회용 숫자가 인증번호(OTP, 일회용 비밀번호)입니다.

이렇게 구분로그인에는 비밀번호, 본인 확인·결제 확인에는 인증번호 칸.

AI에게 이렇게비밀번호는 가려지는 입력칸으로, 인증번호는 숫자 6칸으로 나뉜 OTP 입력으로 만들어줘

20년차 메모OTP 칸을 한 글자씩 나눠 만들면 붙여넣기가 막히는 경우가 많습니다. 문자로 받은 숫자 복사를 한 번에 채울 수 있게 하세요. 인증번호는 받는 시간 제한과 다시 받기 버튼이 세트이고, 모바일에서는 문자에서 자동으로 채워 주는 기능(autocomplete=one-time-code)을 켜 주세요.

05

지우기 vs 보기 Clear vs Show

칸 안의 X는 입력한 글자를 한 번에 지우는 지우기(클리어), 눈 모양은 가려진 글자를 잠깐 보여주는 보기(표시 토글)입니다.

이렇게 구분검색창처럼 처음부터 다시 쓰는 칸이면 지우기, 비밀번호 칸처럼 가려진 값을 확인하고 싶으면 보기.

AI에게 이렇게검색 입력칸에는 글자가 있을 때만 보이는 지우기 X 버튼을, 비밀번호 칸에는 눈 모양 보기 버튼을 넣어줘

20년차 메모지우기는 글자가 있을 때만 나타나야 하고, 눌러도 키보드는 닫히지 않고 칸에 포커스가 남아야 합니다. 보기 버튼은 눈 아이콘이 현재 상태인지 누르면 바뀔 상태인지 헷갈리니 '비밀번호 보기/숨기기' 접근성 이름을 꼭 달아 주세요.

글자 수 vs 입력 제한 Counter vs Max length

'7/10'처럼 지금 몇 자인지만 보여주는 건 글자 수 표시, 한도를 넘으면 더 이상 입력이 안 되게 막는 건 입력 제한입니다.

이렇게 구분SNS 글처럼 넘으면 줄여 쓰게 하려면 글자 수 표시(초과 시 빨강), 전화번호처럼 길이가 딱 정해져 있으면 입력 제한.

AI에게 이렇게후기 입력칸 오른쪽 아래에 현재 글자 수/최대 글자 수를 보여주고, 넘으면 숫자를 빨강으로 바꿔줘

20년차 메모입력 제한만 걸고 아무 말이 없으면 사용자는 키보드가 고장 났다고 생각합니다. 제한이 있으면 반드시 숫자로도 보여주세요. 한글·이모지는 글자 수를 세는 방법(바이트·코드 단위)에 따라 서버와 화면 숫자가 달라질 수 있으니 개발자와 기준을 맞추세요.

07

숫자 키패드 vs 키보드 Numpad vs Keyboard

입력칸을 누르면 숫자판이 올라오느냐, 글자 자판이 올라오느냐를 정하는 설정입니다. 숫자만 받는 칸에는 숫자 키패드를 띄워 주는 게 맞습니다.

이렇게 구분인증번호·금액·수량처럼 숫자만 쓰면 숫자 키패드, 이름·주소·이메일은 일반 키보드.

AI에게 이렇게인증번호 입력칸은 inputmode를 numeric으로 해서 숫자 키패드가 뜨게 하고, 이메일 칸은 이메일용 키보드가 뜨게 해줘

20년차 메모숫자를 받는다고 type=number로 만들면 스크롤로 값이 바뀌거나 0으로 시작하는 번호가 잘리는 문제가 생깁니다. 인증번호·전화번호는 글자로 받되 inputmode만 숫자로 지정하는 쪽이 안전합니다. PC에서는 차이가 보이지 않으니 반드시 실제 폰으로 확인하세요.

08

날짜 입력 vs 날짜 선택 Date input vs Picker

숫자를 직접 타이핑하면 날짜 입력, 칸을 누르면 달력이 열려 눌러서 고르면 날짜 선택(데이트 피커)입니다.

이렇게 구분생년월일처럼 멀고 정확히 아는 날짜는 직접 입력, 예약 날짜처럼 요일과 가까운 날을 보며 고르면 선택.

AI에게 이렇게생년월일은 숫자로 입력하게 하고, 숙소 체크인 날짜는 달력에서 고르는 날짜 선택으로 만들어줘

20년차 메모생일을 달력으로 고르게 하면 1990년으로 가려고 수십 번 눌러야 합니다. 먼 과거는 직접 입력이나 연도 먼저 고르기가 낫습니다. 반대로 예약은 요일이 중요해서 달력이 맞습니다. 직접 입력은 2026-01-15 와 20260115 등 형식 차이를 허용할지 정해야 합니다.

09

필수 vs 선택 Required vs Optional

비우면 다음으로 못 가는 칸은 필수, 비워도 되는 칸은 선택입니다. 칸마다 둘 중 어느 쪽인지 표시해 줘야 합니다.

이렇게 구분필수가 대부분이면 선택에만 '(선택)'을 붙이고, 선택이 대부분이면 필수에만 별표(*)를 붙이는 식으로 적은 쪽을 표시.

AI에게 이렇게필수 입력칸 라벨 옆에는 빨간 별표를, 선택 입력칸 라벨 옆에는 (선택) 문구를 붙여줘

20년차 메모별표만 쓰고 '*는 필수'라는 설명이 없으면 처음 보는 사람은 뜻을 모릅니다. 폼의 칸이 대부분 필수라면 별표를 전부 붙이지 말고 선택 칸에만 '(선택)'을 쓰는 편이 깔끔합니다. 개발에서는 required 속성과 화면 표시가 따로 놀지 않도록 한 곳에서 관리해야 합니다.

10

입력 마스크 Input mask

사용자가 숫자만 쳐도 하이픈·공백이 자동으로 들어가 정해진 모양으로 바뀌는 입력 방식입니다. 전화번호, 카드번호, 사업자번호에 씁니다.

언제 쓰나전화번호·카드번호·사업자등록번호처럼 모양이 정해진 값.

AI에게 이렇게전화번호 입력칸은 숫자만 쳐도 010-1234-5678 모양으로 하이픈이 자동으로 들어가게 해줘

20년차 메모마스크가 커서 위치를 망가뜨려 중간 글자를 고치기 어려운 구현이 많습니다. 붙여넣기와 지우기까지 직접 테스트하세요. 하이픈을 직접 치는 사람도 있으니 어느 쪽이든 받아야 합니다.

올바른 이메일을 입력해 보세요

11

실시간 검증 Inline validation

'제출' 버튼을 누르기 전, 입력하는 그 자리에서 바로 맞는지 알려주는 검증입니다. 맞으면 체크, 틀리면 오류 문구가 뜹니다.

언제 쓰나회원가입의 아이디 중복 확인, 이메일 형식, 비밀번호 규칙처럼 틀리기 쉬운 칸.

AI에게 이렇게이메일 입력칸은 칸을 벗어날 때 형식을 검사하고 올바르면 오른쪽에 체크 표시를 보여줘

20년차 메모한 글자 칠 때마다 '형식이 틀렸습니다'가 뜨면 아직 쓰는 중인 사람에게 짜증만 줍니다. 칸을 벗어난 뒤에 검사하되, 한번 틀렸다가 고치는 중에는 바로 갱신해서 안심시키세요.

칸을 눌러 브라우저 제안이 뜨는지 보세요

12

자동 채우기 Autofill

브라우저나 폰이 저장해 둔 이름·주소·카드번호를 칸에 한 번에 채워 주는 기능입니다. 개발자가 칸에 올바른 이름(autocomplete 속성)을 붙여야 작동합니다.

언제 쓰나회원가입, 배송지, 결제처럼 같은 정보를 반복 입력하는 폼.

AI에게 이렇게배송지 폼의 모든 입력칸에 올바른 autocomplete 속성을 붙여 브라우저 자동 채우기가 되게 해줘

20년차 메모입력칸을 직접 만든 부품으로 대체하면 자동 채우기가 깨지는 경우가 많습니다. 결제나 로그인처럼 중요한 폼은 자동 채우기가 실제로 동작하는지 크롬·사파리에서 직접 확인하세요.
