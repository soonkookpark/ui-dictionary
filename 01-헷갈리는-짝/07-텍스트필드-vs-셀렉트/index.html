01

텍스트 필드 상태 Text field states

입력칸은 하나라도 상황에 따라 모습이 달라지는데, 이 각각을 상태라고 부릅니다. 보통 기본(아직 건드리지 않음), 포커스(커서가 들어옴), 입력 중(값이 있음), 오류(값이 틀림), 비활성(지금은 쓸 수 없음)을 나란히 디자인합니다.

언제 쓰나폼을 디자인하거나 AI에게 입력칸을 시킬 때, 한 가지 모습만이 아니라 다섯 가지 상태를 함께 요청할 때.

AI에게 이렇게이메일 입력칸을 기본, 포커스, 입력 중, 오류, 비활성의 다섯 가지 상태로 구분해서 만들어줘

20년차 메모시안에 기본 상태만 있고 오류와 비활성이 없으면 개발자가 임의로 만들어 서비스마다 제각각이 됩니다. 포커스 상태는 키보드로 이동하는 사용자가 현재 위치를 알려 주는 유일한 표시라서 테두리가 배경과 3:1 이상 대비돼야 합니다. 비활성은 왜 비활성인지 말해 주지 않으면 사용자가 고장으로 오해하니 이유를 문구로 적어 주세요.

02

셀렉트 Select

여러 보기 중에서 정해진 것 하나를 골라 칸에 채우는 입력입니다. 드롭다운, 셀렉트 박스, 콤보 상자라고도 부르며, 텍스트 필드와 달리 목록에 없는 값은 입력할 수 없습니다.

언제 쓰나국가·직무·월처럼 선택지가 정해져 있고 5개 이상일 때. 오타 없이 정해진 값만 받고 싶을 때.

AI에게 이렇게희망 직무는 텍스트 필드가 아니라 선택지 목록에서 고르는 셀렉트로 만들어줘

20년차 메모선택지가 2~4개뿐이면 셀렉트는 한 번 더 눌러야 해서 라디오가 낫습니다. 선택 전 '선택하세요' 같은 안내 항목을 첫 줄에 두되, 선택된 뒤에는 그 항목을 못 고르게 해야 합니다. 모바일에서는 기기 기본 선택창이 뜨는 쪽이 보통 가장 쓰기 편합니다.

03

콤보박스 Combobox

글자를 직접 입력해서 목록을 좁히거나, 목록에서 고를 수도 있는 입력칸입니다. 셀렉트와 텍스트 필드를 합친 모양이며 검색 가능한 셀렉트라고도 합니다.

언제 쓰나선택지가 수십 개 이상인 국가·도시·학교 선택처럼 목록을 스크롤해 찾기 번거로울 때.

AI에게 이렇게도시 입력칸은 글자를 치면 목록이 좁혀지고 목록에서 고를 수도 있는 콤보박스로 만들어줘

20년차 메모목록에 없는 값을 쳤을 때 허용할지 막을지를 정해야 합니다. 허용하면 오타 데이터가 쌓이고, 막으면 사용자가 왜 안 되는지 모릅니다. 한글 입력은 조합 중에도 목록이 갱신되는지 개발과 확인하세요.

04

멀티 셀렉트 Multi select

목록에서 하나가 아니라 여러 개를 고르는 선택입니다. 고른 항목이 칩이나 체크 표시로 남습니다. 셀렉트가 한 개 선택이라면 멀티 셀렉트는 여러 개 선택입니다.

언제 쓰나관심사 태그, 참석자 지정, 필터 조건처럼 중복해서 고르는 입력.

AI에게 이렇게관심 분야는 여러 개를 고르고 선택한 항목이 칩으로 보이는 멀티 셀렉트로 만들어줘

20년차 메모선택된 칩이 많아지면 칸 높이가 한없이 늘어나니 최대 개수나 '+3개 더'로 접는 규칙을 정하세요. 네모 체크로 고르는 모양이 눈에 보이지 않으면 사용자는 여러 개 선택이 되는 줄 모르니 안내 문구가 필요합니다.

05

라디오 그룹 vs 셀렉트 Radio group vs Select

선택지를 전부 펼쳐 놓고 누르면 라디오 그룹, 접어 두었다가 눌러서 펼치면 셀렉트입니다. 보기 개수가 기준이 됩니다.

이렇게 구분보기가 5개 이하이고 비교해서 골라야 하면 라디오 그룹, 6개 이상이거나 자리가 좁으면 셀렉트.

AI에게 이렇게성별처럼 선택지가 세 개 이하면 라디오 그룹으로, 국가 선택처럼 많으면 셀렉트로 만들어줘

20년차 메모보기가 적은데 셀렉트를 쓰면 매번 한 번 더 눌러야 하고 선택지가 숨어 있어 비교도 못 합니다. 반대로 라디오가 10개를 넘으면 화면이 길어지고 스크롤이 먼저 일어납니다. 모바일은 셀렉트를 누르면 기기 기본 선택창이 떠서 라디오보다 빠를 때도 있습니다.

06

네이티브 셀렉트 vs 커스텀 셀렉트 Native vs Custom select

브라우저와 폰이 기본으로 주는 선택 상자를 그대로 쓰면 네이티브, 모양을 우리 디자인에 맞춰 직접 만들면 커스텀입니다.

이렇게 구분접근성과 모바일 사용성이 중요하면 네이티브, 브랜드 디자인이 중요하거나 항목 안에 아이콘·설명이 들어가면 커스텀.

AI에게 이렇게정렬 선택은 기본 네이티브 셀렉트를 쓰고, 직무 선택만 아이콘이 들어간 커스텀 셀렉트로 만들어줘

20년차 메모커스텀 셀렉트는 겉모양만 만들면 끝이 아닙니다. 키보드 위아래·Enter·Esc·글자 입력 이동과 스크린 리더 지원을 전부 다시 만들어야 해서 개발 비용이 크게 늡니다. 모바일에서는 네이티브가 기기 선택창을 열어 주므로 커스텀이 오히려 불편해지는 일이 흔합니다.

07

읽기 전용 vs 비활성 Read-only vs Disabled

값은 보이지만 고칠 수 없는 칸에는 두 종류가 있습니다. 읽기 전용은 선택하고 복사할 수 있고 폼에 포함되며, 비활성은 아예 눌리지도 않고 폼에서 빠집니다.

언제 쓰나고칠 수는 없어도 복사해 가야 하는 값(주문번호, 가입 이메일)은 읽기 전용, 조건이 맞아야 켜지는 칸은 비활성.

AI에게 이렇게가입 이메일은 복사할 수 있는 읽기 전용 칸으로, 다른 조건이 있어야 쓰는 칸은 비활성 스타일로 만들어줘

20년차 메모비활성 칸은 키보드 포커스도 못 받아서 스크린 리더 사용자는 존재 자체를 놓칠 수 있습니다. 비활성을 쓸 때는 왜 지금 못 쓰는지를 가까이에 문구로 적어 주세요. 비활성 칸의 값은 폼 제출에서 빠지니 개발자가 서버로 보내야 하는 값이라면 읽기 전용을 쓰라고 알려 주세요.
