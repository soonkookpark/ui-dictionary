01

알럿 vs 컨펌 Alert vs Confirm

사용자에게 일어난 일을 알리고 '확인' 하나만 있으면 알럿, 하겠냐고 묻고 '취소'와 '확인' 두 길을 주면 컨펌입니다.

이렇게 구분'저장됐어요'처럼 결정할 게 없으면 알럿, '정말 삭제할까요?'처럼 되돌릴 수 없는 일을 앞두고는 컨펌.

AI에게 이렇게저장 완료는 확인 버튼 하나뿐인 알럿으로, 삭제 전에는 취소와 삭제 버튼이 있는 컨펌 대화상자를 띄워줘

20년차 메모알림을 전부 알럿으로 띄우면 사용자는 읽지도 않고 '확인'만 누르게 됩니다. 컨펌의 버튼은 '예/아니오'가 아니라 '삭제'·'취소'처럼 동작을 그대로 쓰세요. 삭제처럼 위험한 동작은 색을 빨강으로 하되, 기본 포커스는 안전한 쪽(취소)에 두는 게 좋습니다.

02

드롭다운 vs 피커 Dropdown vs Picker

작은 상자를 눌러 목록이 아래로 펼쳐지면 드롭다운, 화면 아래에서 올라오는 돌림판을 굴려 맞추면 피커입니다. 모바일에서 휠 피커라고 부르는 것이 이것입니다.

이렇게 구분PC 웹에서 항목이 적당히 많으면 드롭다운, 모바일에서 날짜·시간·숫자처럼 순서가 있는 값은 피커.

AI에게 이렇게웹에서는 드롭다운 셀렉트를, 모바일 생일 입력에는 휠 피커를 사용해줘

20년차 메모모바일에서 웹 드롭다운을 억지로 쓰면 작은 목록 위에서 스크롤이 헷갈리니, 기기가 주는 기본 피커(네이티브)를 믿는 게 대부분 낫습니다. 항목이 5개 이하면 드롭다운 대신 라디오로 풀어 놓는 편이 한 번 덜 누릅니다. 피커는 고른 값을 '확인'으로 확정하는지 돌리자마자 반영하는지 정해서 개발자와 맞추세요.

03

캐러셀 vs 가로 스크롤 Carousel vs Horizontal scroll

한 번에 한 장을 크게 보여주고 점이나 화살표로 넘기면 캐러셀, 카드가 다음 장 끝이 걸쳐 보이게 늘어서서 자유롭게 밀리면 가로 스크롤입니다.

이렇게 구분메인 배너·온보딩처럼 한 장씩 소개하면 캐러셀, 상품·영상 목록처럼 훑어보게 하면 가로 스크롤.

AI에게 이렇게홈 상단에는 점 표시가 있는 배너 캐러셀을, 추천 상품은 옆으로 자유롭게 밀리는 가로 스크롤 목록으로 만들어줘

20년차 메모자동으로 넘어가는 캐러셀은 읽는 중에 사라지고, 두 번째 장부터는 거의 안 봅니다. 중요한 내용은 첫 장에 두고 멈춤 버튼을 달거나 아예 자동 전환을 끄세요. 가로 스크롤은 오른쪽 카드가 반쯤 잘려 보이게 해야 '더 있다'는 걸 압니다. 마우스 사용자는 가로로 밀기 어려우니 웹에서는 화살표 버튼이 필요합니다.

04

상단 바 vs 탭 바 Top bar vs Tab bar

화면 위에서 지금 있는 곳의 제목과 뒤로 가기를 알려주면 상단 바, 화면 아래에서 큰 갈래 사이를 옮겨 다니게 하면 탭 바입니다.

이렇게 구분지금 화면의 이름과 되돌아가기가 필요하면 상단 바, 홈·검색·내 정보처럼 늘 오가는 큰 메뉴는 탭 바.

AI에게 이렇게상세 화면 위에는 뒤로 가기가 있는 상단 바를, 앱 아래에는 홈·검색·내 정보 탭 바를 넣어줘

20년차 메모탭 바 항목은 5개를 넘기지 마세요. 6개부터는 터치가 좁아져서 오작동이 늘고, 넘치는 건 '더보기' 탭으로 묶는 게 표준입니다. 탭 바는 하위 화면으로 들어가도 유지할지 숨길지를 정해야 하는데, 개발에서 화면마다 다르게 구현해 깜빡이는 경우가 많습니다. 웹 PC 화면에서는 탭 바를 위쪽 메뉴나 옆 메뉴로 옮깁니다.

05

페이징 vs 무한 스크롤 Paging vs Infinite scroll

한 쪽씩 번호로 끊어서 보여주면 페이징, 아래로 내릴수록 새 항목이 계속 이어 붙으면 무한 스크롤입니다.

이렇게 구분게시판·검색 결과처럼 위치를 기억하거나 끝을 알아야 하면 페이징, 피드·사진처럼 끝없이 훑어보면 무한 스크롤.

AI에게 이렇게게시판은 페이지 번호가 있는 페이징으로, 피드는 아래로 내리면 이어 붙는 무한 스크롤로 만들어줘

20년차 메모무한 스크롤은 맨 아래에 있는 푸터(회사 정보 등)에 영영 닿지 못하게 만들고, 상세 페이지에서 돌아오면 위치를 잃는 문제가 흔합니다. 뒤로 가기 때 스크롤 위치를 복원하는지 꼭 확인하세요. 페이징은 번호 버튼이 작으면 모바일에서 누르기 어려우니 '더 보기' 버튼으로 바꾸는 절충안도 있습니다.

플로팅 vs 하단 고정 Floating vs Sticky bottom

내용 위에 둥둥 떠서 작게 자리를 차지하면 플로팅 버튼, 화면 아래에 가로로 길게 붙어 있으면 하단 고정 버튼입니다.

이렇게 구분새 글 쓰기처럼 선택적인 주요 동작 하나면 플로팅 버튼, 결제·신청처럼 이 화면의 최종 행동이면 하단 고정 버튼.

AI에게 이렇게목록 화면에는 오른쪽 아래 플로팅 글쓰기 버튼을, 상품 상세에는 구매하기 하단 고정 버튼을 달아줘

20년차 메모플로팅 버튼은 마지막 항목을 가려서 눌러야 할 것을 놓치게 합니다. 목록 맨 아래에 버튼 높이만큼 여백을 주세요. 하단 고정 버튼은 아이폰 아래 홈 바 영역(세이프 에어리어)과 키보드가 올라올 때 가려지는지 확인하세요. 한 화면에 둘을 같이 쓰면 어느 게 주인공인지 모르게 됩니다.

플레이스홀더 vs 라벨 Placeholder vs Label

입력칸 안에 흐리게 적혔다가 글자를 치면 사라지는 건 플레이스홀더, 칸 위에 항상 남아서 무엇을 쓰는 칸인지 알려주는 건 라벨입니다.

이렇게 구분'name@mail.com' 같은 예시는 플레이스홀더, 칸의 이름('이메일')은 반드시 라벨.

AI에게 이렇게모든 입력칸 위에 라벨을 항상 보이게 달고, 플레이스홀더에는 입력 예시만 넣어줘

20년차 메모플레이스홀더만 있는 폼은 입력을 시작하는 순간 무슨 칸이었는지 사라져서, 다 쓰고 나서 확인하기가 어렵습니다. 연한 회색 글자는 명도 대비가 낮아 잘 안 읽히고 이미 입력된 값으로 오해받기도 합니다. 접근성 측면에서도 스크린 리더는 플레이스홀더를 라벨로 읽지 않는 경우가 있어 label 연결이 필요합니다.

08

진행 바 vs 단계 표시 Progress vs Steps

연속된 양이 채워지며 '몇 퍼센트'를 보여주면 진행 바, 정해진 칸으로 나뉘어 '3단계 중 2단계'를 보여주면 단계 표시(스텝)입니다.

이렇게 구분업로드·설치처럼 연속적으로 차오르면 진행 바, 가입·결제처럼 화면이 나뉘어 있으면 단계 표시.

AI에게 이렇게파일 업로드에는 퍼센트가 있는 진행 바를, 결제 화면 위에는 3단계 스텝 표시를 넣어줘

20년차 메모단계마다 입력량이 다른데 진행 바를 3분의 1씩 채우면 사용자가 속았다고 느낍니다. 단계 표시는 이름까지 써야 의미가 있고, 바로 앞 단계로 돌아가 고칠 수 있어야 합니다. 로딩과 입력 단계를 같은 막대 모양으로 섞어 쓰지 마세요.

09

아코디언 vs 더보기 Accordion vs Show more

제목 줄을 누르면 그 자리에서 내용이 접히고 펼쳐지면 아코디언, 일부만 보여준 글이나 목록 끝에서 나머지를 이어서 보여주면 더보기입니다.

이렇게 구분FAQ·약관처럼 제목이 여러 개 있으면 아코디언, 긴 후기나 상품 설명을 미리보기로 줄이면 더보기.

AI에게 이렇게자주 묻는 질문은 한 번에 하나씩 펼쳐지는 아코디언으로, 긴 후기는 두 줄에서 자르고 더보기를 달아줘

20년차 메모아코디언 안에 중요한 정보를 숨기면 사용자는 열어보지 않습니다. 열고 닫는 화살표 방향과 키보드(Enter)로 열리는지를 확인하세요. 더보기는 눌렀는데 접기가 없어 길이가 끝없이 늘어나거나, 글이 짧아 잘리지도 않는데 버튼만 보이는 경우를 막아야 합니다.

파괴적 동작 버튼 Destructive action

삭제·탈퇴처럼 되돌리기 어려운 동작을 하는 버튼입니다. 보통 빨간색으로 표시해 일반 버튼과 구분합니다.

언제 쓰나컨펌 대화상자에서 삭제·초기화·로그아웃 같은 동작을 확인받을 때.

AI에게 이렇게삭제 컨펌의 삭제 버튼은 빨간 파괴적 버튼 스타일로 하고, 취소를 기본 포커스로 해줘

20년차 메모빨간색이 남발되면 진짜 위험한 곳에서 효과가 없어집니다. 정말 위험한 동작은 컨펌 대신 '실행 취소'를 주는 쪽이 사용자에게 더 편한 경우도 많습니다.

스티키 헤더 Sticky header

스크롤을 내려도 화면 위쪽에 달라붙어 따라오는 제목이나 바입니다. CSS의 position: sticky로 만듭니다.

언제 쓰나연락처의 ㄱㄴㄷ 구분 제목, 표의 머리글, 스크롤해도 보여야 하는 상단 바.

AI에게 이렇게목록의 초성 구분 제목에 스티키 헤더를 적용해줘

20년차 메모스티키 요소가 두 개 이상 겹쳐 쌓이면 화면의 절반을 가립니다. 작은 화면에서는 하나만 고정하세요. 앵커 링크로 이동할 때 고정 헤더 뒤에 제목이 숨는 문제는 scroll-margin으로 해결합니다.

12

지연 로딩 Lazy loading

처음부터 전부 불러오지 않고, 화면에 보이기 직전에 필요한 만큼만 불러오는 방식입니다. 무한 스크롤과 이미지 목록에서 속도를 지키는 기본기입니다.

언제 쓰나긴 피드, 이미지가 많은 페이지, 아래쪽 비디오처럼 처음 화면에 없는 것들.

AI에게 이렇게이미지는 화면에 가까워질 때만 불러오도록 지연 로딩을 적용해줘

20년차 메모이미지 자리를 미리 잡아 두지 않으면 지연 로딩이 오히려 화면을 덜컥거리게 합니다. 비율을 고정한 자리표시(스켈레톤)와 함께 쓰세요.
