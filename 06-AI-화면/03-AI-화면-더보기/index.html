언제 쓰나챗봇·글쓰기 도우미·코딩 도우미 등 사용자가 문장으로 요청하는 모든 AI 화면의 하단.

모델 선택기 Model picker

지금 어떤 AI 모델로 답하는지 보여주고 바꿀 수 있게 하는 드롭다운. 이름만 나열하기보다 "빠름·정교함"처럼 차이를 한마디로 붙여 줍니다.

언제 쓰나속도와 품질, 가격이 다른 모델을 여러 개 제공하는 서비스. 입력창 위나 화면 상단 모서리.

AI에게 이렇게입력창 위에 모델 선택기 드롭다운을 넣고, 모델마다 이름 옆에 빠름·균형·정교함 같은 한 단어 설명을 붙여줘

실무 팁모델 이름이 개발자 코드명이면 사용자는 고를 수 없습니다. 차이를 쓸 수 없는 모델은 목록에서 빼는 게 맞습니다. 대화 중간에 모델을 바꾸면 이전 답과 말투가 달라질 수 있으니 바꾼 시점을 대화 안에 표시하세요.

04

새 대화 버튼 New chat button

지금까지의 맥락을 끊고 빈 대화로 시작하는 버튼. AI는 같은 대화 안에서는 앞 내용을 계속 참고하기 때문에, 주제를 바꿀 때는 새 대화가 필요합니다.

언제 쓰나주제가 완전히 바뀔 때, 앞 대화가 답을 이상하게 끌고 갈 때. 보통 사이드바 맨 위나 상단 모서리.

AI에게 이렇게사이드바 맨 위에 새 대화 버튼을 두고, 누르면 지금 대화는 목록에 저장하고 빈 첫 화면을 보여줘

실무 팁입력창에 쓰다 만 글이 있는데 새 대화를 누르면 글이 사라지는 사고가 잦습니다. 임시저장하거나 확인을 받으세요. 그리고 새 대화 버튼이 눈에 안 띄면 사용자는 한 대화를 끝없이 길게 끌고 가서 답 품질이 떨어졌다고 느낍니다.

05

대화 제목 자동 생성 Auto-generated title

첫 질문이나 답을 바탕으로 AI가 대화 목록에 보일 짧은 제목을 스스로 붙여 줍니다. 사용자가 이름을 지을 필요가 없어서 기록이 쌓여도 찾기 쉽습니다.

언제 쓰나대화 기록 목록이 있는 모든 AI 서비스. 제목은 목록·검색 결과·브라우저 탭에 쓰입니다.

AI에게 이렇게첫 답변이 끝나면 대화 내용을 15자 이내로 요약한 제목을 자동으로 만들어 사이드바 목록에 표시하고, 제목을 눌러 직접 고칠 수도 있게 해줘

실무 팁제목이 바뀌는 순간 목록이 흔들리면 눈이 따라가지 못합니다. 제목 자리 너비를 고정하세요. 민감한 내용이 제목에 그대로 노출되는 점도 놓치기 쉽습니다. 어깨 너머로 목록이 보이는 환경을 생각해 직접 고치고 지울 수 있어야 합니다.

06

시스템 메시지 System message · Notice line

사용자도 AI도 말하지 않았는데 대화 사이에 끼는 가운데 정렬의 작은 안내 줄. 말풍선이 아니라서 누가 한 말이 아니라 상태 변화 알림이라는 것을 보여줍니다.

언제 쓰나모델 변경, 대화 이어받기, 기능 꺼짐, 파일 만료처럼 대화 흐름 중간에 알려야 하는 일.

AI에게 이렇게대화 중간에 상태가 바뀌면 말풍선 대신 가운데 정렬된 회색 작은 글씨 한 줄로 시스템 메시지를 끼워 넣어줘

실무 팁말풍선과 같은 모양으로 만들면 AI가 한 말처럼 읽혀 혼란이 옵니다. 색과 정렬을 확실히 다르게 하세요. 반대로 너무 연해서 읽히지 않는 안내가 많은데, 글자는 배경과 4.5:1 이상 대비를 지켜야 합니다.

07

답변 속 코드 블록 Code block + Copy

답 안의 코드를 일반 글과 분리해 고정폭 글꼴 상자에 담고, 상자 모서리에 복사 버튼을 붙인 것. 누르면 버튼 글자가 "복사됨"으로 잠깐 바뀌어 성공을 알려줍니다.

언제 쓰나코드, 명령어, 설정 파일처럼 한 글자도 틀리면 안 되는 내용을 AI가 줄 때.

AI에게 이렇게답변 속 코드는 언어 이름이 적힌 헤더가 있는 코드 블록으로 보여주고, 오른쪽 위 복사 버튼을 누르면 "복사됨"으로 2초간 바뀌게 해줘

실무 팁긴 코드 줄을 줄바꿈하면 들여쓰기가 깨져 읽을 수 없으니 가로 스크롤을 쓰세요. 복사 버튼은 코드가 아직 스트리밍 중일 때도 눌릴 수 있는데, 그러면 반쪽 코드가 복사됩니다. 생성이 끝날 때까지 비활성으로 두는 쪽이 안전합니다.

표·수식 렌더링 Table & math rendering

AI가 글자로 보낸 표나 수식 표기를 화면에서 진짜 표와 수학 기호로 바꿔 그려 주는 처리. 렌더링은 "코드 모양의 글을 최종 화면으로 그려낸다"는 뜻입니다.

언제 쓰나비교표, 일정표, 통계, 수학·과학 설명이 자주 나오는 AI 화면.

AI에게 이렇게AI 답변의 마크다운 표는 실제 표로 그리고, 수식은 수식 기호 렌더링으로 보여줘. 표가 화면보다 넓으면 표 안에서만 가로 스크롤되게 해줘

실무 팁표는 스트리밍 도중에 줄이 하나씩 붙으면서 폭이 계속 변해 화면이 출렁입니다. 표가 끝날 때까지 기다렸다가 한 번에 그리는 편이 낫습니다. 모바일에서 열이 4개를 넘으면 잘리니 가로 스크롤이나 카드형 변환을 미리 정해 두세요.

접히는 생각 과정 Reasoning disclosure

언제 쓰나추론에 시간이 걸리는 모델, 검증 과정이 중요한 분석·계산 답변.

AI에게 이렇게답변 위에 접히는 생각 과정 영역을 두고 기본은 접힌 상태로, 생성 중에는 "생각 중" 한 줄만 보여주다가 끝나면 펼쳐 볼 수 있게 해줘

실무 팁펼쳐진 과정이 최종 답보다 더 눈에 띄면 주객이 바뀝니다. 글자 크기와 색을 낮추세요. 과정 글이 논리적으로 보인다고 해서 답이 맞다는 보장은 아니라는 점에서, 과정을 근거처럼 디자인하면 과신을 부릅니다.

실행 전 승인 요청 Human in the loop · Confirm before action

AI가 되돌리기 어려운 일을 하기 직전에 멈추고 사람의 확인을 받는 화면. 사람이 중간에 끼어 최종 결정을 한다는 뜻의 Human in the loop라고 부릅니다.

언제 쓰나삭제, 결제, 메일 발송, 외부 서비스 수정처럼 실행하면 되돌리기 어려운 AI 작업 직전.

AI에게 이렇게AI가 파일 삭제나 메일 발송을 하기 전에 무엇을 할지 한 줄로 설명하는 승인 카드를 띄우고, 허용과 거절 버튼을 두고 거절하면 아무 일도 하지 않게 해줘

실무 팁모든 작업마다 승인을 받으면 사용자가 내용을 안 읽고 허용만 누르는 승인 피로가 생기고, 그때부터 승인은 안전장치가 아니라 장식입니다. 읽기 같은 안전한 일은 묻지 말고, 위험한 일만 무엇이 바뀌는지 구체적으로 보여주고 물으세요. 이번만 허용과 항상 허용은 구분해야 합니다.

결과물 패널 Canvas · Artifact panel

대화는 왼쪽에 두고, AI가 만든 문서·코드·화면 같은 결과물만 오른쪽 옆 패널에 따로 보여주는 구조. 대화 속에 길게 섞이지 않아 고쳐 가며 다듬기 좋습니다.

언제 쓰나긴 글, 코드, 표, 미리보기가 있는 화면처럼 결과물을 여러 번 고쳐야 하는 작업.

AI에게 이렇게긴 결과물은 대화창 안에 붙이지 말고 오른쪽 옆 패널에 열어줘. 패널은 닫기와 복사 버튼이 있고, 좁은 화면에서는 전체 화면 시트로 바뀌게 해줘

실무 팁패널이 열리는 순간 대화 영역이 확 줄면 읽던 위치를 잃습니다. 대화 쪽 스크롤 위치는 그대로 유지하세요. 모바일에서는 나란히 놓을 폭이 없으니 시트나 탭 전환으로 바꿔야 하고, 이걸 빼먹은 시안이 많습니다.

13

변경 비교 Diff view

AI가 고친 부분을 이전과 이후로 나란히 또는 위아래로 놓고, 지워진 줄은 빨강, 새로 생긴 줄은 초록으로 표시한 화면. diff는 "차이"라는 뜻입니다.

언제 쓰나AI가 문서나 코드를 수정했을 때 무엇이 바뀌었는지 검토하고 수락할 때.

AI에게 이렇게입력창에 / 를 입력하면 입력창 위에 명령 목록이 뜨게 하고, 글자를 더 치면 목록이 걸러지고 위아래 키와 엔터로 선택하게 해줘

실무 팁숨은 기능이라 존재를 알려 주지 않으면 아무도 쓰지 않습니다. 입력창 안내 문구에 "/ 로 명령"이라고 한 번은 보여주세요. 메뉴가 열린 상태에서 엔터가 메시지 전송으로 먹혀 버리는 오류가 흔하니 선택과 전송을 분리해야 합니다.

@로 파일 지정 @ mention

입력창에서 @ 를 치고 파일이나 사람, 페이지를 골라 "이것을 보고 답해"라고 콕 집어 지정하는 방식. 고른 대상은 입력창 안에서 알약 모양 칩으로 바뀝니다.

언제 쓰나여러 문서나 폴더 중 특정한 것만 참고시킬 때, 코드 편집기에서 파일을 지정할 때.

AI에게 이렇게입력창에서 @ 를 치면 파일과 페이지 목록이 뜨고, 고르면 입력창 글 안에 칩으로 들어가 AI가 그 파일만 참고하게 해줘

실무 팁칩이 입력창 글 한가운데 들어가면 지우거나 커서를 옮길 때 한 글자씩이 아니라 칩이 통째로 지워지는 동작을 개발자와 맞춰야 합니다. 목록이 수백 개일 때는 최근 항목을 먼저 보여주고 글자로 걸러지게 해야 합니다.

오래 걸리는 작업을 AI가 뒤에서 하는 동안 사용자는 다른 일을 하고, 끝나면 알림으로 알려주는 방식. 기다리는 화면을 붙잡아 두지 않는 것이 핵심입니다.

언제 쓰나깊은 조사, 대량 파일 처리, 몇 분 이상 걸리는 에이전트 작업.

AI에게 이렇게오래 걸리는 작업은 백그라운드로 돌리고 진행 중임을 목록에 표시하며, 끝나면 화면 아래 토스트와 푸시 알림으로 알리고 누르면 결과로 이동하게 해줘

실무 팁창을 닫아도 계속 도는지 사용자는 모릅니다. 시작할 때 "닫아도 계속돼요"를 먼저 말해 주세요. 알림을 눌렀는데 결과가 아니라 홈으로 가면 신뢰를 잃으니 딥링크로 정확한 결과를 열어야 합니다. 실패 알림도 성공 알림만큼 중요합니다.

안전 차단 안내와 신고 Safety refusal & report

AI가 요청에 답하지 않을 때, 거절만 하지 않고 이유와 대안, 잘못 막힌 경우를 알릴 신고 길을 같이 보여주는 화면. 사용자가 이유 없이 막혔다고 느끼지 않게 합니다.

언제 쓰나안전·정책상 답할 수 없는 요청, 또는 AI가 잘못 판단해 정상 요청을 막았을 때.

AI에게 이렇게AI가 답변을 거절하면 빨간 오류 대신 중립적인 안내 카드로 이유를 한 줄 쓰고, 대신 도울 수 있는 일을 버튼으로 제안하고, 잘못 차단됐다면 신고할 수 있는 링크를 달아줘

실무 팁거절 화면을 빨간 오류처럼 만들면 사용자는 자신이 비난받았다고 느낍니다. 중립적인 색과 말투로 쓰세요. 다만 이유를 너무 자세히 쓰면 우회 방법을 알려 주는 셈이 되니, 위험한 분야는 어디까지 설명할지를 정책 담당자와 먼저 정해야 합니다.
