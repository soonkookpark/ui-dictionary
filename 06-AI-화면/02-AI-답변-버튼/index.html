01

다시 생성 Regenerate

같은 질문으로 새 답을 만들어 지금 답과 바꾸는(또는 버전으로 쌓는) 버튼입니다. 눌렀을 때 이전 답이 어떻게 되는지가 이 버튼의 핵심입니다. 화면에 무엇이 보이는지는 앞 주제의 다시 생성에서 다뤘습니다.

언제 쓰나생성 중에는 못 누르게 비활성(또는 숨김), 답이 끝난 뒤 마지막 답변에만 활성화합니다. 오래된 답변에는 달지 않습니다.

AI에게 이렇게다시 생성 버튼은 답변이 끝난 뒤 마지막 답변 아래에만 보이게 하고, 생성 중에는 비활성화해줘

20년차 메모생성 중에 눌리게 두면 요청이 두 번 나가서 답이 뒤섞입니다. 눌렀을 때 새 답이 도착하기 전 이전 답을 남길지 지울지도 정해야 합니다. 지우면 되돌릴 수 없어 불안해합니다.

02

복사 Copy

답변 전체(또는 코드 블록 하나)를 클립보드에 담는 버튼입니다. 누르면 아이콘이 체크로 잠깐 바뀌어 "복사됐다"는 피드백을 줍니다.

언제 쓰나답변이 끝난 뒤에 보여줍니다. 코드 블록은 생성 중에도 블록 위에 달아 두기도 하지만 끝나기 전 복사하면 잘린 내용이 담깁니다.

AI에게 이렇게답변 아래 복사 버튼을 누르면 내용을 클립보드에 담고 아이콘이 2초간 체크 표시와 "복사됨"으로 바뀌게 해줘

20년차 메모복사할 때 마크다운 기호(별표, 샵)까지 담을지 서식을 뺀 글만 담을지 정해야 합니다. 붙여 넣는 곳(메일, 문서, 메신저)에 따라 기대가 다릅니다. 복사 권한이 막힌 환경(주소가 https가 아닐 때)에서는 실패 안내도 필요합니다.

03

좋아요·싫어요 Feedback

답변 품질을 평가해 서비스에 알리는 버튼입니다. 누르면 선택 상태가 되고, 싫어요는 이유를 고르는 단계가 따라붙는 경우가 많습니다. 모양은 앞 주제에서 다뤘으니 여기서는 누른 뒤의 흐름을 봅니다.

언제 쓰나답변이 끝난 뒤에만 보여줍니다. 쓰는 중에 평가하면 글이 반쯤 나온 상태를 평가하게 됩니다.

AI에게 이렇게싫어요를 누르면 이유 칩(부정확함, 도움 안 됨, 너무 김)을 펼치고, 좋아요를 누르면 감사 문구를 보여줘

20년차 메모평가를 눌렀는데 아무 반응이 없으면 누른 줄 모르고 계속 누릅니다. 취소하려고 다시 눌렀을 때 선택이 해제되는지 정해야 하고, 이유 입력은 선택 사항이어야 합니다. 평가 데이터에 대화 내용이 같이 저장된다면 그 사실도 고지해야 합니다.

04

출처 Citations

답변이 참고한 자료 목록을 펼치거나 접는 버튼입니다. 평소엔 "출처 3개"만 보이고, 누르면 제목과 링크가 열립니다. 문장 옆 번호 칩이 아니라 목록 단위의 접힘 동작을 다룹니다.

언제 쓰나답변이 끝난 뒤 보여줍니다. 생성 중에는 번호가 바뀔 수 있으니 숨기거나 "찾는 중"으로 대신합니다.

AI에게 이렇게답변 아래 "출처 N개" 버튼을 두고 누르면 출처 제목과 링크 목록이 펼쳐지게 해줘

20년차 메모출처를 눌러 나간 사용자가 뒤로 돌아왔을 때 대화가 그대로 있어야 합니다. 새 탭으로 열어 주세요. 출처가 0개인 답변에 빈 알약을 보여주는 실수도 많으니 없으면 버튼 자체를 숨겨야 합니다.

05

이어 묻기 칩 Follow-up chips

답변 바로 아래에 나타나는 "다음에 이렇게 물어보세요" 알약들입니다. 누르면 그 문장이 다음 질문으로 전송됩니다. 빈 화면의 시작용 칩과 달리 방금 답한 내용에 맞춰 바뀝니다.

언제 쓰나답변이 완전히 끝난 뒤에 나타나게 합니다. 생성 중에 보이면 사용자가 끝나기 전에 눌러 대화가 꼬입니다.

AI에게 이렇게답변 생성이 끝나면 아래에 이어 묻기 칩 3개를 부드럽게 나타내고, 새 질문을 보내면 이전 칩은 사라지게 해줘

20년차 메모칩이 사용자의 입력창을 가리거나 계속 쌓이면 대화 화면이 지저분해집니다. 마지막 답변에만 붙이세요. 칩 누르기 전에 바로 전송할지, 입력창에 채워서 고칠 기회를 줄지는 개발자와 합의해 둬야 합니다.

메시지 입력

06

멈춤 버튼 Stop

생성 중인 답변을 그 자리에서 끊는 버튼으로, 보통 네모 모양입니다. 보내기 버튼과 같은 자리를 쓰며 생성이 끝나면 다시 보내기로 돌아옵니다. 눌러도 이미 나온 글은 지워지지 않고 남습니다.

언제 쓰나생성 중에만 보여줍니다. 끝난 뒤에는 보내기 버튼으로 바꿔야 하며, 둘이 동시에 보이면 안 됩니다.

AI에게 이렇게답변을 생성하는 동안 보내기 버튼 자리에 멈춤 버튼을 보여주고, 누르면 생성을 중단하되 이미 나온 글은 남겨줘

20년차 메모멈춘 뒤 이어서 받을지 다시 생성할지 갈림길이 생깁니다. "멈춤 → 계속 생성" 버튼이 따라붙어야 막다른 길이 안 됩니다. 단축키(Esc)와 접근성 이름("생성 멈추기")도 같이 챙기세요. 서버에서는 중단 요청이 실제로 비용을 멈추는지 확인해야 합니다.

07

스트리밍 Streaming

글자가 나오는 모양보다 여기서는 스크롤을 따라가는 동작에 집중합니다. 새 글이 나오면 화면이 자동으로 따라 내려가고, 사용자가 위로 올리면 따라가기를 멈추며 "맨 아래로" 버튼이 나타납니다.

언제 쓰나생성 중에만 자동 따라가기가 켜집니다. 끝나면 꺼지고 "맨 아래로" 버튼도 사라집니다.

AI에게 이렇게스트리밍 중에는 맨 아래로 자동 스크롤하되 사용자가 위로 올리면 멈추고, 그때 "맨 아래로" 버튼을 보여줘

20년차 메모자동 스크롤이 읽는 사람을 계속 끌어내리는 것이 가장 짜증스러운 AI 화면 문제입니다. 사용자가 손가락이나 휠로 움직인 순간 바로 멈춰야 합니다. 모바일에서 키보드가 올라온 상태에서는 마지막 줄이 입력창 뒤에 가려지는지도 확인하세요.

08

생각 중 표시 Thinking

점 3개가 아니라 펼쳐 볼 수 있는 "생각하는 중" 줄입니다. 답이 나오기 전 AI가 정리한 과정을 요약해서 보여주고, 끝나면 "8초 동안 생각함"처럼 접힌 채 남습니다.

언제 쓰나생성 중에는 펼쳐 있거나 반짝이게 두고, 답이 시작되면 접어서 답변 위에 작게 남깁니다. 완료 후에도 누르면 다시 볼 수 있어야 합니다.

AI에게 이렇게답변 위에 반짝이는 "생각하는 중" 줄을 보여주고, 누르면 생각 과정이 펼쳐지며 답이 시작되면 "N초 동안 생각함"으로 접히게 해줘

20년차 메모보여주는 과정이 실제 내부 계산과 다를 수 있으니 "AI가 이렇게 판단했다"는 확신을 주는 문구는 피하세요. 글자 반짝임은 움직임 줄이기 설정을 켠 사용자에게는 끄고 정지된 상태로 보여줘야 합니다.

부산 맛집 알려줘

09

질문 수정 Edit prompt

보낸 질문을 고쳐서 다시 보내는 버튼으로, 내 말풍선 옆에 연필로 나타납니다. 누르면 그 아래 대화가 새 질문 기준으로 다시 만들어진다는 점이 앞 주제의 고쳐 묻기 화면과 이어집니다.

언제 쓰나답이 끝난 뒤에만 켭니다. 생성 중에 고치려면 먼저 멈춤을 눌러야 하고, 보통 마지막 질문에만 허용합니다.

AI에게 이렇게내 말풍선에 올리면 연필 버튼이 나타나고, 누르면 입력칸으로 바뀌며 다시 보내면 아래 답변을 새로 생성하게 해줘

20년차 메모올릴 때만 보이는 연필은 모바일에서 존재하지 않습니다. 터치 화면에서는 항상 보이게 하거나 길게 누르기로 대체하세요. 수정 후 이전 대화를 버릴지 가지로 남길지에 따라 데이터 구조가 달라지니 개발 전에 정해야 합니다.

10

계속 생성 Continue generating

답이 길이 제한이나 멈춤 때문에 중간에 끊겼을 때 이어서 쓰게 하는 버튼입니다. 처음부터 다시 쓰는 다시 생성과 달리 끊긴 지점부터 이어 갑니다.

언제 쓰나끊긴 답변 바로 아래. 정상 완료된 답변에는 보이면 안 됩니다.

AI에게 이렇게답변이 길이 제한으로 끊기면 아래에 계속 생성 버튼을 보여주고 누르면 같은 말풍선에 이어 붙여줘

20년차 메모끊겼다는 사실을 글 끝에 "…"만 남기면 사용자는 AI가 일부러 그만뒀다고 오해합니다. "길이 제한으로 멈췄어요"처럼 이유를 한 줄 알려 주세요. 이어 붙일 때 문장이 중복되는 문제는 개발 쪽에서 점검해야 합니다.

11

오류 후 다시 시도 Retry on error

답변 생성이 실패했을 때 그 자리에서 같은 요청을 다시 보내는 버튼입니다. 다시 생성은 "마음에 안 드는 답을 새로", 다시 시도는 "실패한 요청을 그대로 한 번 더"입니다.

언제 쓰나네트워크 끊김, 서버 오류, 시간 초과처럼 답이 만들어지지 못한 경우에만.

AI에게 이렇게답변 생성이 실패하면 말풍선을 오류 상태로 바꾸고 다시 시도 버튼을 보여줘. 입력한 질문은 그대로 보존해줘

20년차 메모실패했을 때 사용자가 쓴 긴 질문이 사라지는 것이 가장 큰 사고입니다. 입력은 반드시 보존하세요. "오류가 발생했습니다"만 쓰지 말고 연결 문제인지 길이 초과인지 알려 줘야 사용자가 다음 행동을 고릅니다.

단순화한 예시: 읽는 동안 막대가 움직입니다

12

읽어주기 Read aloud

답변을 소리로 읽어 주는 버튼입니다. 읽는 동안 소리 막대 같은 표시로 진행 중임을 알리고, 다시 누르면 멈춥니다. 시각이 불편한 사용자와 이동 중인 사용자에게 모두 쓰입니다.

언제 쓰나답변이 끝난 뒤에 보여줍니다. 생성 중에는 문장이 계속 바뀌어 읽기 어렵습니다.

AI에게 이렇게답변 아래 읽어주기 버튼을 두고, 읽는 동안 막대 애니메이션을 보여주며 다시 누르면 멈추게 해줘

20년차 메모표, 코드, 링크 주소처럼 소리 내어 읽으면 이상한 내용을 어떻게 처리할지 정해야 합니다. 스크린리더 사용자는 이미 자기 읽기 도구가 있어 겹쳐 재생되는 일이 없게 해야 합니다.
