컴포넌트 상태

01

기본 Default · Enabled

아무 일도 일어나지 않았을 때의 평소 모습. 기본 상태(rest state)라고도 하며, 다른 모든 상태는 이 모습에서 얼마나 달라지는지로 설계합니다.

언제 쓰나화면이 처음 열렸을 때, 사용자가 아직 건드리지 않은 모든 버튼과 입력창.

AI에게 이렇게버튼의 기본 상태 색은 주색으로 두고, 나머지 상태는 기본 색에서 파생해서 만들어줘

20년차 메모입력창의 기본 상태에서 placeholder(안내 글자)를 라벨 대신 쓰면 입력을 시작하는 순간 질문이 사라집니다. 라벨은 항상 보이게 두고 placeholder는 예시만 담으세요.

마우스를 올려 보세요

02

호버 Hover

마우스 포인터가 요소 위에 올라가 있는 상태. "여기 누를 수 있어요"라고 눌러 보기 전에 미리 알려주는 신호입니다. 보통 색을 한 단계 진하게 하거나 그림자를 줍니다.

언제 쓰나PC 웹의 버튼, 링크, 카드, 표의 행처럼 누를 수 있는 모든 것.

AI에게 이렇게버튼에 호버 상태를 넣어서 마우스를 올리면 배경이 한 단계 진해지게 해줘

20년차 메모터치 기기에는 호버가 없습니다. 호버에서만 보이는 메뉴나 툴팁은 휴대폰에서는 영영 못 봅니다. 호버로 정보를 숨기지 말고, 호버는 "덤"으로만 쓰세요.

한 번 누른 뒤 Tab 키로 이동해 보세요

03

포커스 Focus · 키보드 포커스 링

키보드로 지금 "선택되어 있는" 요소. Tab 키를 누르면 다음 요소로 옮겨가고, 이때 요소를 둘러싸는 테두리를 포커스 링(focus ring)이라고 합니다. 호버가 마우스용이라면 포커스는 키보드용입니다.

언제 쓰나모든 버튼·링크·입력창. 키보드 사용자, 스크린 리더 사용자, 외부 키보드를 단 태블릿 사용자에게 필수입니다.

AI에게 이렇게모든 버튼과 입력창에 포커스 상태를 넣고, 키보드로 이동할 때만 보이는 두꺼운 포커스 링을 그려줘

20년차 메모"못생겼다"며 outline: none 으로 링을 지워버리는 일이 가장 흔한 사고입니다. 지우려면 반드시 더 눈에 띄는 대체 표시를 넣어야 합니다. 링이 배경색과 비슷해서 안 보이는 경우도 시안 단계에서 확인하세요.

마우스 버튼을 누르고 있는 동안만 바뀝니다

04

눌림 Pressed · Active

손가락이나 마우스 버튼이 요소를 누르고 있는 동안의 상태. "눌렸어요"라는 즉각적인 확인이며, 살짝 작아지거나 어두워지는 식으로 표현합니다. 눌려 있다가 놓는 순간 실제 동작이 일어납니다.

언제 쓰나버튼, 목록 행, 카드처럼 눌러서 동작하는 모든 요소. 모바일에서는 특히 중요합니다.

AI에게 이렇게버튼에 눌림 상태를 넣어서 누르는 동안 95% 크기로 작아지고 더 어두운 색이 되게 해줘

20년차 메모모바일에서는 손가락이 요소를 가리기 때문에 눌림 표시가 없으면 눌렸는지 알 수 없어 두 번 누릅니다. 또 목록 행 전체가 눌리는 곳은 버튼만이 아니라 행 전체의 눌림 색을 그려야 합니다.

눌러도 아무 반응이 없습니다

05

비활성 Disabled

"지금은 누를 수 없음"을 뜻하는 상태. 흐린 색으로 바꾸고 클릭도 받지 않습니다. 필수 항목을 다 채우기 전의 제출 버튼이 대표적입니다.

언제 쓰나조건이 맞지 않아 지금은 실행할 수 없는 버튼, 권한이 없는 메뉴, 이미 처리 중인 동작.

AI에게 이렇게필수 입력이 모두 채워지기 전까지 제출 버튼을 비활성 상태로 두고, 왜 못 누르는지 아래에 문구로 알려줘

20년차 메모비활성 버튼은 "왜 안 되는지"를 말해주지 않는 것이 가장 큰 약점입니다. 흐린 색은 대비 기준에서도 면제되어 눈에 잘 안 띄니, 이유를 옆에 글로 적거나 눌렀을 때 오류로 알려주는 편이 더 친절합니다.

끝날 때까지 다시 누를 수 없음

06

로딩 Loading · Busy

요청을 보내고 결과를 기다리는 상태. 비활성의 한 종류지만 "고장이 아니라 일하는 중"이라는 뜻을 따로 알려줍니다. 버튼 안에 작은 스피너와 "저장 중" 같은 글을 넣습니다.

언제 쓰나저장·제출·결제처럼 버튼을 눌러 서버에 요청을 보내는 동작. 로딩 방식 자체는 로딩 패턴 페이지를 참고하세요.

AI에게 이렇게제출 버튼에 로딩 상태를 추가해서 요청 중에는 스피너와 "저장 중" 글자를 보이고 중복 클릭을 막아줘

20년차 메모로딩 상태를 빠뜨리면 사용자가 버튼을 연타해서 같은 요청이 여러 번 갑니다. 그리고 로딩 중에 글자가 바뀌면 버튼 너비가 변해 옆 요소가 밀리니, 최소 너비를 고정해 두세요.

눌러서 선택·해제해 보세요

07

선택됨 Selected · Checked · Active

여러 개 중에서 "이것이 골라져 있다"는 상태. 체크박스는 체크됨(checked), 탭이나 메뉴는 현재 위치(current·active), 목록은 선택됨(selected)처럼 이름이 조금씩 다르지만 같은 개념입니다.

언제 쓰나필터 칩, 탭, 체크박스, 라디오, 메뉴에서 지금 보고 있는 항목, 목록에서 고른 행.

AI에게 이렇게필터 칩에 선택됨 상태를 만들어서 선택하면 주색 배경에 흰 글자와 체크 아이콘이 보이게 해줘

20년차 메모선택됨을 색 하나로만 구분하면 색약 사용자와 흑백 화면에서는 안 보입니다. 체크 아이콘이나 굵은 글씨, 밑줄을 함께 쓰세요. 그리고 선택됨 위에 마우스를 올린 모습(선택+호버)도 따로 그려야 합니다.

올바른 이메일 주소를 입력해 주세요 주소를 끝까지 고쳐 보세요. 오류가 사라집니다

08

오류 Error · Invalid

입력한 값이 규칙에 맞지 않을 때의 상태. 빨간 테두리만이 아니라 무엇이 틀렸고 어떻게 고치는지 알려주는 문장이 같이 있어야 완성입니다.

언제 쓰나이메일 형식 오류, 비밀번호 규칙 위반, 이미 쓰는 아이디, 필수 항목 누락 등 입력을 검사하는 모든 곳.

AI에게 이렇게입력창에 오류 상태를 만들어서 빨간 테두리와 아이콘, 해결 방법을 알려주는 문구를 아래에 보여줘

20년차 메모입력하자마자 빨갛게 만들면 사용자는 쓰는 중에 야단맞는 기분이 듭니다. 입력창을 벗어났을 때 검사하는 게 기본입니다. "잘못된 값입니다"처럼 모호한 문구와 색만 쓰는 표시도 피하세요.

읽기 전용: 선택하고 복사할 수 있음 비활성: 선택도 복사도 안 됨

09

읽기 전용 Read-only

값은 보이지만 고칠 수 없는 상태. 비활성(Disabled)과 달리 포커스를 받고, 글자를 드래그해 복사할 수 있고, 스크린 리더도 읽어 줍니다. 값을 "보여주기 위한" 입력창입니다.

언제 쓰나주문 번호, 추천 코드, 공유 링크, 계약 완료 후의 입력 내용처럼 사용자가 확인하거나 복사만 하는 값.

AI에게 이렇게주문 번호는 읽기 전용 입력창으로 보여주고, 옆에 복사 버튼을 달아줘

20년차 메모읽기 전용을 비활성처럼 흐리게 칠하면 "안 되는 것"으로 오해해서 복사하지 않습니다. 배경만 살짝 구분하고 글자는 또렷하게 두세요. 개발자에게 disabled 와 readonly 중 무엇을 쓸지 정확히 말해 주지 않으면 서로 바뀌어 구현되곤 합니다.

10

상태 매트릭스 State matrix

한 컴포넌트의 모든 상태를 표 하나에 모아 그린 것. 줄은 컴포넌트 종류(주 버튼, 보조 버튼), 칸은 상태입니다. 디자이너가 개발자에게 넘기는 가장 믿을 만한 명세서입니다.

언제 쓰나디자인 시스템의 컴포넌트를 처음 정의할 때, 개발 전달 직전의 점검, 버튼·입력창·카드·탭처럼 상태가 많은 요소.

AI에게 이렇게버튼의 모든 상태를 한 화면에 나열한 상태 매트릭스 페이지를 만들어줘

20년차 메모기본 상태 한 장만 그려 넘기면 나머지 아홉 상태는 개발자가 알아서 "그럴듯하게" 만들고, 그 결과는 대개 디자이너의 눈에 안 찹니다. 매트릭스를 그리다 보면 빠진 상태(오류인데 비활성인 경우 등)도 시안 단계에서 발견합니다.
