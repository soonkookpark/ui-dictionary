01

주색·보조색·강조색 Primary · Secondary · Accent

주색은 브랜드를 대표하고 주 버튼에 쓰는 색, 보조색은 주색을 받쳐주는 연한 색이나 보조 버튼, 강조색은 딱 한 곳에 시선을 모을 때만 쓰는 색입니다.

언제 쓰나브랜드 색을 정할 때, 버튼 위계를 나눌 때(주 버튼은 주색, 보조 버튼은 보조색), 배지·알림 점 같은 눈에 띄어야 하는 곳.

AI에게 이렇게주색은 인디고, 보조색은 연한 인디고, 강조색은 주황으로 정해서 CSS 변수로 만들고 버튼에 적용해줘

20년차 메모강조색을 여기저기 쓰면 강조가 아니라 소음입니다. 화면 하나에 강조색은 한두 군데만 허용하세요. 또 주색과 강조색을 보색(정반대 색)으로 고르면 나란히 놓았을 때 눈이 아픕니다. 채도 높은 색끼리 큰 면적으로 붙여 놓지 마세요.

02

시맨틱 컬러 Semantic color

색의 모양이 아니라 의미로 이름 붙인 색. "초록"이 아니라 "성공(success)", "빨강"이 아니라 "오류(danger)"라고 부릅니다. 보통 성공·경고·오류·정보 네 가지를 먼저 정합니다.

언제 쓰나토스트, 알림 배너, 입력 오류, 상태 배지, 차트의 증감 표시처럼 색이 의미를 전달하는 모든 곳.

AI에게 이렇게성공, 경고, 오류, 정보 네 가지 시맨틱 컬러를 글자색과 배경색 쌍으로 CSS 변수에 정의해줘

20년차 메모문화권마다 색의 의미가 다릅니다. 국내 증권앱은 상승이 빨강이고 해외는 초록인 것처럼요. 시맨틱 컬러를 "빨강 = 위험"으로 고정하면 상승을 빨강으로 쓰는 화면과 충돌합니다. 의미 이름이 있어야 이럴 때 한 곳만 바꿔 대응할 수 있고, 항상 아이콘이나 문구를 함께 쓰세요.

blue-600green-600→color-action→btn-bg
원시 → 의미 → 컴포넌트. 가운데 연결만 바꿨습니다

03

디자인 토큰 Design token

색, 간격, 글자 크기 같은 디자인 값에 이름을 붙여 저장한 것. 코드에서는 CSS 변수가 그 역할을 합니다. 보통 원시값(blue-600) → 의미값(color-action) → 컴포넌트값(button-bg) 세 단계로 이어서 만듭니다.

언제 쓰나디자인 시스템을 만들 때, 다크 모드·브랜드 변경·여러 앱 지원이 필요할 때, 디자이너와 개발자가 같은 이름으로 대화하고 싶을 때.

AI에게 이렇게색을 디자인 토큰 3단계(원시, 의미, 컴포넌트)로 나눠서 CSS 변수로 정의하고, 컴포넌트는 의미 토큰만 참조하게 해줘

20년차 메모컴포넌트가 원시값(blue-600)을 직접 가져다 쓰기 시작하면 토큰을 만든 의미가 사라집니다. 규칙은 하나, 화면의 부품은 항상 "의미 토큰"만 부른다는 것입니다. 반대로 작은 프로젝트에서 3단계를 전부 만들면 과합니다. 두 단계(원시+의미)로 시작해도 충분합니다.

04

색 단계 Color scale · 50~900

한 가지 색을 가장 밝은 50부터 가장 어두운 900까지 열 단계 안팎으로 나눈 팔레트. 숫자가 클수록 어둡습니다. 보통 500~600이 "대표색", 50~100이 연한 배경, 800~900이 어두운 글자에 쓰입니다.

언제 쓰나호버·눌림처럼 같은 색의 진하기가 필요할 때, 연한 배경과 진한 글자 쌍을 만들 때, 다크 모드를 만들 때.

AI에게 이렇게주색 인디고의 50부터 900까지 색 단계를 만들어 CSS 변수로 정의해줘

20년차 메모단순히 색을 어둡게 하면 칙칙해져서, 어두운 쪽 단계는 채도를 조금 낮추거나 색조를 살짝 돌려서 맞춰야 합니다. 색 단계마다 흰 글자가 가능한지(4.5:1)를 표로 미리 정리해 두면, 개발자가 "이 위에 어떤 글자색?"이라고 물어볼 일이 사라집니다.

05

중립색 Neutral · Gray scale

회색 계열의 색 단계. 글자, 테두리, 배경, 구분선처럼 화면에서 가장 넓은 면적을 차지합니다. 브랜드 색을 5% 정도 섞은 회색은 화면의 분위기가 주색과 어울려 보입니다.

언제 쓰나본문 글자(900 근처), 보조 글자(600), 비활성(400), 테두리(200), 배경(50). 글자와 배경을 정할 때마다.

AI에게 이렇게순수 회색 대신 주색 색조를 살짝 섞은 중립색 10단계를 만들어 글자·테두리·배경 변수로 나눠줘

20년차 메모본문을 순수 검정(#000)으로 쓰면 흰 배경에서 너무 날카로워 눈이 피곤합니다. 아주 진한 회색이나 남색 계열을 쓰세요. 반대로 보조 글자를 너무 연하게 쓰면 대비 기준 미달이 되니, 중립색 표에 어떤 단계가 글자로 쓸 수 있는지 표시해 두세요.

06

다크 모드 Dark mode

어두운 배경에 밝은 글자를 쓰는 화면 테마. 흰색과 검정을 뒤집는 반전이 아니라, 같은 토큰 이름에 어두운 값을 따로 정해 갈아 끼우는 것입니다. 데모에서 주색이 더 밝은 값(인디고 300)으로 바뀌는 것에 주목하세요.

언제 쓰나야간 사용이 많은 앱, 영상·사진 위주 서비스, 개발자 도구, 사용자가 기기 설정에서 다크를 켠 모든 경우.

AI에게 이렇게의미 토큰에 다크 모드 값을 따로 정의하고, prefers-color-scheme 에 따라 자동으로 바뀌게 해줘

20년차 메모순수 검정(#000) 배경은 흰 글자와 대비가 너무 강해서 오히려 번져 보이니, 짙은 남색이나 아주 진한 회색을 씁니다. 다크 모드에서는 그림자가 안 보이므로 높이는 그림자 대신 면의 밝기 차이로 표현합니다. 흰 배경에 맞춰 만든 로고와 일러스트가 다크에서 사라지는 것도 흔한 사고입니다.

07

엘리베이션 Elevation · 그림자 단계

요소가 화면에서 얼마나 "위로 떠 있는지"를 그림자의 세기로 표현하는 단계. 바닥에 붙은 카드는 0단계, 메뉴·팝오버는 중간, 모달은 가장 높은 단계처럼 위에 있을수록 그림자가 크고 흐립니다.

언제 쓰나카드, 드롭다운, 바텀시트, 모달, 눌렀을 때 떠오르는 버튼처럼 겹침의 순서를 알려줄 때.

AI에게 이렇게그림자를 엘리베이션 0부터 3까지 네 단계로 정의해서 카드, 메뉴, 모달에 단계별로 적용해줘

20년차 메모그림자 값을 요소마다 새로 만들면 화면에 일곱 가지 그림자가 섞여 지저분합니다. 3~4단계만 정하고, 높이가 의미하는 바(카드=1, 메뉴=2, 모달=3)도 같이 정하세요. 진한 검정 그림자는 촌스러워 보이니 주색이나 남색을 섞은 투명한 그림자가 낫습니다.

08

모서리 반경 Radius scale

모서리를 얼마나 둥글게 할지를 몇 단계로 정해 둔 것. 같은 서비스에서 버튼은 10px, 카드는 20px, 칩은 끝까지 둥글게(full)처럼 요소 종류마다 쓰는 단계가 정해져 있습니다.

언제 쓰나버튼, 입력창, 카드, 이미지, 칩, 모달. 서비스의 성격(딱딱한지 친근한지)을 정하는 가장 쉬운 도구이기도 합니다.

AI에게 이렇게모서리 반경을 4, 10, 20, 완전 둥글게 네 단계 CSS 변수로 만들고 요소별로 적용해줘

20년차 메모겹친 요소의 안쪽 반경은 바깥 반경에서 간격을 뺀 값이어야 자연스럽습니다. 카드(20px)에 12px 안쪽 여백을 두고 그 안에 이미지를 넣으면 이미지는 8px이 맞습니다. 이 규칙을 모르면 모서리가 어색하게 벌어져 보입니다.

09

간격 스케일 Spacing scale · 4/8pt grid

여백과 간격에 쓸 숫자를 4나 8의 배수(4, 8, 12, 16, 24, 32…)로만 제한하는 규칙. 4pt 그리드, 8pt 그리드라고도 부릅니다. 간격을 "대충 보기 좋게"가 아닌 정해진 목록에서 고르게 합니다.

언제 쓰나카드 안쪽 여백(padding), 요소 사이 간격(gap), 화면 가장자리 여백, 목록 행의 높이.

AI에게 이렇게모든 여백과 간격을 4px 단위 간격 스케일 변수로 정의하고 임의의 숫자는 쓰지 않게 해줘

20년차 메모8의 배수만 고집하면 작은 아이콘 주변이 너무 넓어져서, 촘촘한 곳에서는 4를 허용하는 게 현실적입니다. 또 같은 요소 안의 간격은 좁게, 다른 묶음 사이는 넓게(가까이 있으면 한 묶음) 주는 것이 스케일 선택의 진짜 기준입니다. 숫자만 맞추고 이 관계를 놓치지 마세요.

10

60-30-10 규칙 60-30-10 rule

화면 면적의 60%는 바탕색, 30%는 보조색, 10%는 강조색으로 칠하라는 색 배분 공식. 처음 색 조합을 잡을 때 쓰는 출발점이며, 정확히 지켜야 하는 법칙은 아닙니다.

언제 쓰나랜딩 페이지, 앱의 홈 화면, 브랜드 색을 처음 화면에 입힐 때. 색이 너무 많아 산만해 보일 때의 점검 기준.

AI에게 이렇게이 화면의 색 비율을 60-30-10 규칙에 맞춰서 바탕 흰색, 보조 연한 인디고, 강조 주황으로 정리해줘

20년차 메모숫자를 면적 그대로 믿지 말고 "강조색은 가장 작게, 가장 한 곳에"라는 원칙으로 읽으세요. 사진·영상이 화면을 채우는 서비스에서는 이 비율이 의미가 없습니다. 이럴 땐 사진이 바탕이고 UI 색은 그 위에서 읽히기만 하면 됩니다.

11

상태 색 State layer

호버·포커스·눌림 상태를 색을 일일이 새로 정하지 않고, 원래 색 위에 글자색을 반투명하게 한 겹 덮어 만드는 방식입니다. 보통 호버 8%, 포커스 12%, 눌림 16%처럼 투명도만 다릅니다. 구글 머티리얼 디자인에서 널리 알려졌습니다.

언제 쓰나색이 다른 버튼이 여러 종류일 때, 다크 모드까지 같은 규칙으로 호버를 처리하고 싶을 때.

AI에게 이렇게버튼의 호버, 포커스, 눌림 색을 따로 만들지 말고 상태 색 레이어를 투명도 8%, 12%, 16%로 덮어서 처리해줘

20년차 메모모든 버튼이 색마다 호버 색을 각각 가지면 색 하나를 바꿀 때 상태 색 네 개를 다시 손봐야 합니다. 레이어 방식은 이 부담을 없애지만, 이미 아주 진하거나 아주 연한 색 위에서는 변화가 거의 안 보일 수 있으니 실제로 눌러 보며 투명도를 조정하세요.
