01

WCAG와 등급 WCAG · Level A / AA / AAA

WCAG(웹 콘텐츠 접근성 지침)는 접근성을 판단하는 국제 기준 문서입니다. 기준마다 A(최소), AA(권장), AAA(최고) 등급이 붙고, 보통 "AA를 맞춘다"가 목표가 됩니다.

언제 쓰나접근성 요구사항을 적을 때, 공공기관·금융·쇼핑처럼 법이나 계약으로 기준을 요구받을 때.

AI에게 이렇게이 화면이 WCAG AA 기준을 만족하는지 명도 대비, 키보드 이동, 대체 텍스트 순서로 점검해줘

실무 팁AAA를 한 번에 목표로 삼으면 일정이 무너집니다. AA를 먼저 확실히 하고, 한 서비스 안에서도 본문처럼 중요한 곳만 AAA 수준으로 올리는 게 현실적입니다. 점검 도구가 알려주는 점수만 믿지 말고 실제로 키보드로 한 번 써 보세요.

이 글자는 흐려요
실패 2.2:1

02

명도 대비 Contrast ratio

글자색과 배경색의 밝기 차이를 1:1(차이 없음)부터 21:1(검정과 흰색)까지로 나타낸 비율. 일반 글자는 4.5:1 이상, 큰 글자와 아이콘·테두리는 3:1 이상이 AA 기준입니다.

언제 쓰나본문, 버튼 글자, 안내 문구, 입력창 테두리. 특히 회색 보조 글자와 사진 위에 올린 글자.

AI에게 이렇게모든 글자와 배경의 명도 대비를 계산해서 4.5:1 미만인 조합을 찾아 더 진한 색으로 바꿔줘

실무 팁연한 회색 placeholder와 비활성 버튼이 가장 자주 걸립니다. 모니터에서는 예뻐 보여도 햇빛 아래 휴대폰에서는 안 보입니다. 그리고 그라데이션이나 사진 위의 글자는 가장 밝은 지점 기준으로 재야 합니다.

한 번 누른 뒤 Tab 키로 두 버튼을 오가 보세요

03

포커스 링 Focus ring

키보드로 이동할 때 "지금 여기"를 알려주는 테두리. 오른쪽 버튼처럼 링을 지우면 키보드 사용자는 자기가 어디 있는지 알 수 없습니다. 상태로서의 포커스는 컴포넌트 상태 페이지에서도 다룹니다.

언제 쓰나누를 수 있는 모든 요소. 링은 주변 색과 3:1 이상 대비가 나야 보입니다.

AI에게 이렇게모든 인터랙티브 요소에 키보드 포커스 링을 3px 두께로 보이게 하고, 링을 지우는 CSS는 없애줘

실무 팁어두운 배경 위에서는 흰 링, 밝은 배경에서는 진한 링이 필요합니다. 한 가지 색으로 모든 곳을 해결하려다 안 보이는 곳이 생깁니다. 또 카드의 모서리에서 링이 잘리지 않는지, 부모의 overflow: hidden 에 가려지지 않는지도 확인하세요.

24px · 잘못 눌림
vs
44px 이상 · 안전

04

터치 영역 Touch target

손가락이 눌러서 반응하는 실제 범위. 보이는 아이콘이 작아도 점선처럼 누르는 범위는 넓게 잡습니다. 애플은 44x44pt, 구글 머티리얼은 48x48dp를 권장합니다.

언제 쓰나닫기(X), 하트, 더보기(...), 체크박스 같은 작은 아이콘 버튼과 인접한 링크 목록.

AI에게 이렇게아이콘 버튼의 보이는 크기는 그대로 두고 터치 영역을 48px 이상으로 넓혀줘

실무 팁시안에서는 아이콘 크기만 보고 넘어가서 영역이 24px밖에 안 되는 일이 흔합니다. 영역은 넓히되 눌리는 곳끼리 겹치지는 않게 간격도 챙기세요. PC 웹은 마우스라 작아도 되지만, 같은 화면이 태블릿에서 열린다는 걸 잊으면 안 됩니다.

"image 1234 점 jpg"
vs
"해가 뜬 풀밭 풍경 사진"

05

대체 텍스트 Alt text

이미지를 볼 수 없는 사람과 이미지가 안 뜨는 상황을 위해 그림 대신 읽히는 설명. HTML에서는 alt 속성에 적고, 스크린 리더(화면을 소리로 읽어주는 프로그램)가 그 글을 읽어 줍니다.

언제 쓰나내용을 전달하는 사진, 그래프, 버튼 역할을 하는 이미지. 장식뿐인 그림은 비워 두어(alt="") 읽지 않게 합니다.

AI에게 이렇게모든 이미지에 의미 있는 대체 텍스트를 달고, 장식용 이미지는 빈 alt로 처리해줘

실무 팁"이미지", "사진"처럼 뻔한 단어나 파일명을 넣으면 없는 것보다 못합니다. 그림이 무엇을 말하려는지를 적으세요. 그래프라면 "3월에 매출이 가장 높음"처럼 결론을 적고, 글자가 들어간 배너 이미지는 그 글자를 그대로 alt에 옮겨야 합니다.

한 번 누른 뒤 Tab, 거꾸로는 Shift+Tab

06

키보드 탐색 Keyboard navigation · Tab order

마우스 없이 Tab, Enter, 스페이스, 방향키만으로 모든 기능을 쓸 수 있어야 한다는 원칙. Tab 키가 요소를 지나가는 순서를 탭 순서(tab order)라고 하며, 기본은 화면의 읽는 순서입니다.

언제 쓰나모든 화면. 메뉴, 탭, 드롭다운, 모달처럼 직접 만든 컴포넌트는 특히 빠지기 쉽습니다.

AI에게 이렇게마우스 없이 Tab과 Enter만으로 이 폼을 끝까지 작성할 수 있게 탭 순서를 화면 순서와 맞춰줘

실무 팁눌리는 것처럼 보이는 div 는 Tab 키가 그냥 지나칩니다. 버튼은 버튼 태그로 만들어야 키보드가 공짜로 따라옵니다. 탭 순서가 시각 배치와 어긋나면 키보드 사용자는 화면이 제멋대로 뛴다고 느끼니, 화면을 CSS로 재배치할 때 순서를 꼭 확인하세요.

"닫기, 버튼"

"버튼"

07

스크린 리더 라벨 aria-label

글자가 없는 요소에 소리로 읽힐 이름을 붙이는 속성. 아이콘만 있는 버튼은 눈으로는 X 모양이지만, 라벨이 없으면 스크린 리더는 그냥 "버튼"이라고만 읽어서 무슨 버튼인지 알 수 없습니다.

언제 쓰나닫기(X), 검색(돋보기), 더보기(...), 하트처럼 글자 없는 아이콘 버튼. 화면에 글자가 이미 있다면 따로 필요 없습니다.

AI에게 이렇게아이콘만 있는 모든 버튼에 aria-label을 달고, 아이콘 자체는 스크린 리더가 읽지 않게 숨겨줘

실무 팁라벨은 모양이 아니라 동작을 적어야 합니다. 하트 아이콘이면 "하트"가 아니라 "좋아요". 상태가 바뀌는 버튼(좋아요/좋아요 취소)은 라벨도 같이 바뀌어야 하고, 눈에 보이는 글자가 있으면 그 글자를 라벨에 그대로 포함시키세요.

색만 표시색만 표시
성공실패
켜 보세요. 위쪽 줄은 구분이 안 됩니다

08

색에만 의존하지 않기 Don't rely on color alone

정보를 색 하나로만 전하지 말고 아이콘, 글자, 모양, 밑줄을 함께 쓴다는 규칙. 색을 구분하기 어려운 색각 이상(색약·색맹) 사용자와 흑백 인쇄, 햇빛 아래 화면을 모두 지켜줍니다.

언제 쓰나성공/실패 표시, 입력 오류, 차트의 범례, 링크, 선택됨 상태, 재고·주문 상태 표.

AI에게 이렇게오류와 성공 상태는 색만 쓰지 말고 아이콘과 문구를 함께 넣어줘

실무 팁빨강과 초록 막대 그래프는 색약 사용자에게 같은 색으로 보이는 대표 사고입니다. 검수할 때 시안을 흑백으로 바꿔 한 번 보는 습관이 가장 싸고 효과적입니다. 본문 속 링크도 색만 다르면 밑줄이 있어야 합니다.

단순화한 예시. 실제로는 기기 설정을 따릅니다

09

모션 줄이기 Reduced motion

사용자가 기기 설정에서 "동작 줄이기"를 켜면 화면 전환·튀는 효과·자동 재생 같은 움직임을 줄이거나 없애는 배려. CSS의 prefers-reduced-motion 이라는 조건으로 알아낼 수 있습니다.

언제 쓰나크게 움직이는 전환, 패럴랙스(배경이 다르게 움직이는 효과), 자동 재생 영상과 캐러셀, 계속 반복되는 애니메이션.

AI에게 이렇게prefers-reduced-motion 이 켜진 사용자에게는 큰 움직임 애니메이션을 끄고 페이드로만 전환해줘

실무 팁어지럼증이나 멀미를 느끼는 사용자에게 큰 움직임은 실제로 불편을 넘어 증상을 일으킵니다. 애니메이션을 "모두 끄기"보다 큰 이동·확대는 빼고 투명도 변화는 남기는 식으로 의미 전달은 유지하세요. 그리고 5초 넘게 자동으로 움직이는 것에는 멈춤 버튼이 있어야 합니다.

10

글자 확대 대응 Text scaling · Dynamic Type

사용자가 기기 설정에서 글자를 크게 키워도 화면이 깨지지 않고 읽히는 것. iOS의 Dynamic Type, 안드로이드의 글꼴 크기 설정이 같은 개념이며, 웹에서는 브라우저의 글자 크기와 200% 확대까지를 기준으로 봅니다.

언제 쓰나버튼, 탭 바, 카드, 표의 칸처럼 글자가 들어가는 상자. 고령 사용자가 많은 서비스에서는 특히 중요합니다.

AI에게 이렇게글자 확대 대응을 위해 버튼과 카드의 높이를 고정하지 말고 글자 크기에 맞춰 늘어나게 해줘

실무 팁시안은 늘 기본 크기 하나로만 그려져서 확대하면 글자가 잘리고 줄이 겹칩니다. 높이 고정(height) 대신 최소 높이(min-height)를 쓰고, 글자 크기는 px 대신 상대 단위(rem)로 두세요. 하단 탭 바는 글자가 커지면 한 줄에 안 들어가니, 어떻게 줄일지 미리 정해두어야 합니다.

11

포커스 트랩 Focus trap

모달이 열려 있는 동안 키보드 포커스가 모달 안에서만 돌게 가두는 것. 뒤쪽 화면으로 포커스가 새면 키보드·스크린 리더 사용자는 안 보이는 곳을 헤매게 됩니다. 닫으면 열었던 버튼으로 포커스를 되돌려 줍니다.

언제 쓰나모달, 바텀시트, 전체 화면 메뉴처럼 뒤 화면을 막고 뜨는 모든 겹침 화면.

AI에게 이렇게모달에 포커스 트랩을 넣어서 Tab이 모달 안에서만 돌고, Esc로 닫으면 처음 눌렀던 버튼으로 포커스가 돌아가게 해줘

실무 팁직접 만든 모달에서 가장 자주 빠지는 기능입니다. 웹에서는 dialog 태그의 showModal() 이 이 일을 대부분 해주니 새로 구현하기 전에 먼저 써 보세요. 반대로 모달이 아닌 가벼운 팝오버(툴팁, 드롭다운)에는 트랩을 걸면 안 됩니다. 사용자가 빠져나갈 길이 없어집니다.
