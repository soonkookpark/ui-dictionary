01

내비게이션 레일 Navigation rail

화면 왼쪽 가장자리에 세로로 선 좁은 메뉴 막대. 아이콘 위에 짧은 글자를 붙이고, 아래 탭바를 옆으로 눕힌 것으로 이해하면 쉽습니다. 항목이 많은 사이드바(드로어)와 달리 아이콘만 남겨 폭을 줄입니다.

언제 쓰나태블릿이나 가로로 넓은 창에서 최상위 메뉴 3~5개를 항상 보이게 둘 때. 폰에서는 하단 탭바, 넓어지면 레일로 바꿉니다.

AI에게 이렇게화면 폭이 768px 이상이면 하단 탭바 대신 왼쪽에 아이콘과 라벨이 있는 내비게이션 레일을 보여줘

실무 팁라벨을 빼고 아이콘만 두면 처음 쓰는 사람은 아이콘 뜻을 맞히는 퀴즈를 풀게 됩니다. 항목이 6개를 넘으면 레일이 아니라 접히는 사이드바로 가야 하고, 폭이 좁아졌다 넓어지는 경계에서 탭바와 레일이 어떻게 바뀌는지는 시안에 꼭 그려야 개발자가 헤매지 않습니다.

02

메가 메뉴 Mega menu

메뉴에 마우스를 올리면 목록 한 줄이 아니라 넓은 패널이 열리며 여러 묶음의 링크가 한꺼번에 보이는 메뉴. 드롭다운 메뉴를 크게 키운 것입니다.

언제 쓰나쇼핑몰이나 대형 포털처럼 카테고리가 많고 두 단계 이상으로 나뉘는 웹사이트의 상단 메뉴.

AI에게 이렇게상단 메뉴의 "상품"에 마우스를 올리면 세 열로 나뉜 메가 메뉴가 열리고, 키보드 포커스로도 열리게 해줘

실무 팁마우스를 올려야만 열리는 메뉴는 터치 화면에서 존재하지 않는 메뉴입니다. 탭하면 열리는 동작과 모바일용 대체 메뉴를 같이 정하세요. 또 대각선으로 마우스를 옮기다 패널이 닫혀 버리는 짜증이 흔하니, 닫히기 전에 0.2초 정도 여유를 두는 게 좋습니다.

03

스크롤 스파이 Scrollspy

글을 읽으며 내려가면 지금 읽는 위치에 맞춰 옆의 목차가 자동으로 강조되는 것. 목차 항목을 누르면 그 부분으로 부드럽게 이동하는 동작과 보통 한 세트입니다.

언제 쓰나문서, 도움말, 약관, 긴 제품 소개 페이지처럼 한 화면에 섹션이 여러 개 이어지는 긴 글.

AI에게 이렇게긴 문서 페이지 오른쪽에 목차를 고정하고, 스크롤 스파이로 현재 읽는 섹션을 강조해줘

실무 팁마지막 섹션이 화면보다 짧으면 끝까지 내려도 그 항목이 강조되지 못하는 버그가 거의 항상 납니다. 마지막 섹션 아래에 여백을 주거나 "맨 끝이면 마지막 항목 강조" 규칙을 넣으세요. 고정 헤더가 있다면 이동 위치를 헤더 높이만큼 내려야 제목이 가려지지 않습니다.

04

라이트박스 Lightbox

썸네일을 누르면 화면을 어둡게 덮고 그림만 크게 띄우는 보기 방식. 페이지를 이동하지 않고 그 자리에서 크게 보고 닫으면 원래 위치로 돌아옵니다. 팝업 창(모달)의 한 종류입니다.

언제 쓰나갤러리, 상품 상세의 사진 확대, 게시글의 첨부 이미지처럼 목록에서 사진을 크게 훑어볼 때.

AI에게 이렇게썸네일을 누르면 라이트박스로 큰 사진을 보여주고, 좌우 화살표와 Esc 키, 바깥 클릭으로 닫히게 해줘

실무 팁닫기 수단이 하나뿐인 라이트박스가 많습니다. 바깥 클릭, X 버튼, Esc 키, 모바일에서는 아래로 쓸어 내리기까지 갖춰야 합니다. 사진 설명(alt)과 "3 / 12" 같은 위치 표시가 없으면 스크린리더 사용자는 지금 어디인지 알 수 없고, 열린 동안 뒤 화면이 스크롤되지 않게 잠그는 것도 잊기 쉽습니다.

05

사이드 패널 Side panel · Inspector

화면 한쪽(보통 오른쪽)에서 밀려 나와 선택한 대상의 상세·설정을 보여주는 패널. 디자인 툴의 속성 창처럼 계속 붙어 있으면 인스펙터라고 부르고, 필요할 때만 나오면 슬라이드오버(slide-over)라고도 합니다.

언제 쓰나목록이나 표에서 한 줄을 고르고 자세히 보거나 고치고 싶은데, 목록 맥락은 잃고 싶지 않을 때.

AI에게 이렇게표의 행을 클릭하면 오른쪽에서 사이드 패널이 밀려 나와 상세 정보를 보여주고, 닫아도 표 위치는 유지해줘

실무 팁패널이 열릴 때 뒤의 표를 밀어내는지, 위에 덮는지를 먼저 정하세요. 표가 밀려 줄어들면 열이 깨지고, 덮으면 선택한 행이 가려질 수 있습니다. 패널 안에서 고친 값을 닫을 때 저장할지 버릴지 묻는 규칙도 빠뜨리기 쉽습니다.

06

스플릿 뷰 Split view · Master-detail

화면을 둘로 나눠 왼쪽은 목록(master), 오른쪽은 선택한 항목의 내용(detail)을 동시에 보여주는 구성. 이메일 앱과 메모 앱의 기본 모양입니다. 사이드 패널과 달리 두 영역이 항상 같은 비중으로 붙어 있습니다.

언제 쓰나메일, 채팅, 설정, 파일 관리처럼 항목을 빠르게 넘나들며 내용을 확인해야 하는 넓은 화면.

AI에게 이렇게폭이 넓으면 왼쪽 목록과 오른쪽 상세의 스플릿 뷰로 보여주고, 모바일에서는 목록과 상세를 별도 화면으로 나눠줘

실무 팁가장 큰 함정은 좁은 화면입니다. 폰에서는 나란히 둘 수 없으니 목록 화면에서 상세 화면으로 넘어가는 흐름과 뒤로 가기를 따로 설계해야 합니다. 그리고 아무것도 선택하지 않은 첫 상태의 오른쪽 빈 영역에 "항목을 선택하세요" 같은 안내를 꼭 두세요.

07

트리 뷰 Tree view

폴더 안에 폴더가 들어 있는 계층 구조를 들여쓰기와 펼침 화살표로 보여주는 목록. 탐색기의 왼쪽 폴더 창이 대표적입니다. 한 번에 한 단계씩 펼쳐서 필요한 곳만 봅니다.

언제 쓰나파일·폴더, 조직도, 카테고리 설정, 문서 목차처럼 깊이가 일정하지 않은 부모-자식 데이터.

AI에게 이렇게폴더 구조를 트리 뷰로 보여주고, 화살표로 펼침과 접힘, 방향키로 항목 이동이 되게 해줘

실무 팁트리는 깊어질수록 이름이 잘리고 가로 스크롤이 생깁니다. 들여쓰기는 16px 안팎으로 작게 하고 긴 이름은 마우스를 올리면 전체가 보이게 하세요. 접근성 쪽에서는 방향키 조작(위·아래 이동, 오른쪽 펼치기, 왼쪽 접기)이 표준이라 그냥 링크 목록으로 만들면 키보드 사용자가 불편합니다.

08

칸반 보드 Kanban board

작업을 카드로 만들어 "할 일 / 진행 중 / 완료" 같은 열에 놓고, 카드를 끌어 다음 열로 옮기며 진행 상황을 보는 방식. 트렐로(Trello)나 지라(Jira) 보드가 대표적입니다. 같은 데이터를 표로 보는 것과 달리 "지금 어디에 쌓였는가"가 한눈에 보입니다.

언제 쓰나단계가 분명한 작업 흐름을 팀이 함께 관리할 때. 채용 지원자, 영업 건, 개발 작업.

AI에게 이렇게할 일, 진행 중, 완료 세 열의 칸반 보드를 만들고 카드를 드래그해서 열 사이로 옮길 수 있게 해줘

실무 팁"진행 중" 열에 카드가 20장 쌓이면 보드가 아니라 쓰레기통입니다. 열마다 동시에 둘 수 있는 개수 제한(WIP 제한)을 정하는 게 칸반의 본뜻입니다. 화면 설계에서는 열이 많아질 때 가로 스크롤, 열이 비었을 때 빈 상태, 터치에서 길게 눌러 끌기와 스크롤이 충돌하는 문제를 챙기세요.

09

태그 입력 Tag input · Token field

입력창 안에 글자를 쓰고 Enter(또는 쉼표)를 치면 작은 알약(칩)으로 굳어져 쌓이는 입력칸. 받는 사람 칸이나 해시태그 칸이 이 모양입니다. 칩 선택 필터(chip)와 달리 사용자가 직접 새 값을 만들어 넣습니다.

언제 쓰나값이 여러 개이고 개수가 정해져 있지 않을 때. 이메일 수신자, 키워드, 해시태그, 담당자 지정.

AI에게 이렇게키워드를 태그 입력으로 받아서 Enter를 치면 칩이 되고, 중복은 막고, 칩의 x를 누르면 삭제되게 해줘

실무 팁Enter를 쳐야 칩이 된다는 걸 모르고 글만 쓰고 저장 버튼을 누르면 마지막 값이 사라집니다. 입력칸을 벗어날 때(blur)도 칩으로 확정하세요. 이메일 칸이라면 형식이 틀린 칩을 빨갛게 표시하고, 붙여넣기로 쉼표가 섞인 여러 개가 들어오는 경우도 처리해야 합니다.

파일을 여기에 끌어놓으세요또는 눌러서 선택
내 컴퓨터의 파일을 끌어 올려 보세요

10

파일 드롭존 Dropzone

파일을 끌어다 놓을 수 있는 점선 영역. 파일이 위에 올라오면 색이 바뀌어 "놓아도 된다"고 알려주고, 눌러서 고르는 방법도 함께 제공합니다. 일반 파일 선택 버튼을 크게 키우고 끌어놓기를 더한 것입니다.

언제 쓰나사진·문서 업로드, 데이터 가져오기처럼 파일을 자주 올리는 데스크톱 웹 화면.

AI에게 이렇게점선 드롭존에 파일을 끌어놓거나 클릭해서 올릴 수 있게 하고, 끌어올 때 배경색을 바꾸고 허용 형식과 용량 제한을 안내해줘

실무 팁끌어놓기만 되는 드롭존은 키보드와 모바일 사용자를 막습니다. 반드시 "파일 선택" 버튼이 같이 있어야 합니다. 허용 형식, 최대 용량, 여러 개 가능 여부를 영역 안에 미리 적고, 실패한 파일은 어느 파일이 왜 실패했는지 줄마다 알려주세요.

11

범위 슬라이더 Range slider

손잡이가 2개라서 최솟값과 최댓값을 한 줄에서 함께 고르는 슬라이더. 손잡이가 하나인 일반 슬라이더(값 하나 선택)와 구분됩니다. 두 손잡이 사이가 선택된 구간입니다.

언제 쓰나가격대, 연도, 면적, 나이처럼 "얼마에서 얼마까지"로 걸러내는 필터.

AI에게 이렇게가격 필터를 손잡이 두 개짜리 범위 슬라이더로 만들고, 아래에 선택한 최소·최대 값을 숫자로 보여줘

실무 팁손잡이만으로는 정확한 값을 맞추기 어려우니 숫자 입력칸을 같이 두세요. 손잡이가 서로 교차하지 않게 막거나 자동으로 바꿔 주는 규칙, 값이 한쪽에 몰린 데이터(가격 대부분이 싼 쪽)에서의 눈금 간격도 정해야 합니다. 손잡이 크기는 터치 기준 최소 44pt를 지키세요.

#4F46E5
네모를 누르면 브라우저의 컬러 피커가 열립니다

12

컬러 피커 Color picker

색을 눈으로 보며 고르는 도구. 색판을 누르거나 견본을 고르고, 필요하면 #4F46E5 같은 16진수 코드(HEX)를 직접 넣습니다. 견본 몇 개만 주는 것은 팔레트(색 견본 모음)라고 부릅니다.

언제 쓰나테마 색, 글자 색, 태그 색, 차트 색처럼 사용자가 색을 직접 정하게 허락하는 설정 화면.

AI에게 이렇게테마 색 설정에 컬러 피커를 넣고, 추천 견본 6개와 HEX 직접 입력칸, 선택한 색의 미리보기를 보여줘

실무 팁색을 자유롭게 고르게 하면 흰 글자가 안 보이는 노란색을 고르는 사용자가 반드시 나옵니다. 고른 색 위의 글자 대비(4.5:1)를 자동 계산해 경고하거나 글자색을 알아서 뒤집으세요. 색만으로 상태를 나누지 않도록 색 이름이나 모양도 함께 쓰는 게 접근성의 기본입니다.

눌러 보세요

13

액션 시트 Action sheet

모바일에서 버튼을 누르면 아래에서 올라오는 "무엇을 할까요?" 선택지 묶음. 선택지가 곧바로 실행되는 행동이라는 점이 입력 내용을 담는 바텀 시트와 다릅니다. 맨 아래에 따로 떨어진 "취소"가 특징입니다.

    인라인 편집 Inline edit

    수정 화면으로 이동하지 않고 글자가 있는 그 자리에서 바로 눌러 고치는 방식. 평소에는 글자처럼 보이다가 누르면 입력칸으로 바뀝니다. 별도의 "수정" 버튼과 폼 화면을 거치는 편집과 대비됩니다.

    언제 쓰나문서 제목, 표의 셀, 카드 이름, 할 일 제목처럼 짧고 자주 고치는 한 줄 텍스트.

    AI에게 이렇게제목을 클릭하면 그 자리에서 입력칸으로 바뀌는 인라인 편집으로 만들고, Enter로 저장, Esc로 취소하게 해줘

    실무 팁평소 모양이 글자와 똑같으면 고칠 수 있다는 사실을 아무도 모릅니다. 마우스를 올렸을 때 테두리나 연필 아이콘으로 알려야 하고, 터치 화면에는 hover가 없으니 연필 아이콘을 항상 보이게 두세요. 저장 실패 시 원래 값으로 되돌릴지, 입력을 유지하고 오류를 보일지와 Esc 취소도 빠뜨리기 쉽습니다.
