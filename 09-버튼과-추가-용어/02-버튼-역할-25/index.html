버튼 역할 25가지

버튼은 모양보다 하는 일로 부릅니다

이름을 쓰고 눌러 보세요(비우면 막힙니다)

01

제출 버튼 Submit button

입력한 내용을 서버로 보내는 폼의 마지막 버튼. HTML에서는 type="submit"인 버튼이고, 엔터 키로도 눌립니다. 저장 버튼과 달리 "보냄"이 핵심이라 보낸 뒤의 결과 화면이 따라옵니다.

언제 쓰나회원가입, 문의하기, 신청서, 설문처럼 여러 칸을 채운 뒤 한 번에 보내는 폼.

AI에게 이렇게문의 폼 맨 아래에 제출 버튼을 넣고, 누르면 버튼 안에 스피너를 보여준 뒤 "접수됐어요"로 바뀌게 해줘

20년차 메모라벨을 "제출"이나 "확인"으로 두지 말고 "신청하기", "문의 보내기"처럼 무엇을 보내는지 쓰세요. 누른 뒤에는 중복 전송을 막고(버튼 잠금), 성공만이 아니라 서버 오류와 필수값 누락 때 어느 칸이 문제인지도 보여 줘야 합니다. 비활성 버튼으로 막기보다 눌렀을 때 비어 있는 칸을 알려 주는 쪽이 사용자가 덜 헤맵니다.

댓글 쓰기

02

취소 버튼 Cancel button

하던 일을 멈추고 아무것도 바꾸지 않은 채 빠져나가는 버튼. 입력 중이던 내용은 버립니다. 닫기(X)와 달리 "하려던 동작을 포기한다"는 뜻이 들어 있습니다.

언제 쓰나글쓰기, 수정, 결제 확인창처럼 진행 중인 작업이 있고 되돌아갈 수 있어야 할 때.

AI에게 이렇게글쓰기 폼에 텍스트 형태의 취소 버튼을 만들고, 내용이 있을 때 누르면 한 번 더 확인하게 해줘

20년차 메모취소와 닫기를 같은 말로 쓰면 "취소했는데 저장돼 있다"는 혼란이 생기니 하나로 정하세요. 확인창에서 "취소"가 모호할 때는 "계속 쓰기", "작성 취소"처럼 행동으로 풀어 쓰세요. 입력한 내용이 많은데 확인 없이 날리면 가장 큰 불만이 됩니다. 안드로이드는 취소를 왼쪽, iOS는 취소를 왼쪽 아래나 별도 시트로 두는 경향이 있어 플랫폼 관습을 따르세요.

03

닫기 버튼 Close · X button

지금 보고 있는 팝업, 배너, 시트를 치우고 원래 화면으로 돌아가는 버튼. 모양은 보통 X 아이콘이고, 아무것도 저장하거나 취소하지 않고 그냥 가립니다. 디스미스(Dismiss)라고도 합니다.

언제 쓰나팝업, 이벤트 배너, 안내 토스트, 바텀 시트의 오른쪽 위.

AI에게 이렇게쿠폰 배너 오른쪽 위에 닫기 버튼(X)을 달고 aria-label 과 Esc 키 닫기를 같이 넣어줘

20년차 메모X 아이콘은 보이는 건 16px이어도 누르는 영역은 44pt 이상이어야 합니다. 광고 팝업의 X를 일부러 작고 흐리게 만들면 사용자 신뢰를 잃고, 앱스토어 심사에서도 지적받습니다. aria-label은 "닫기"보다 "쿠폰 안내 닫기"처럼 무엇을 닫는지 적으세요. 닫은 뒤 다시 보이게 할지 아닌지(오늘 하루 보지 않기)도 같이 정해야 합니다.

주문 내역 항목을 눌러 상세로 들어가세요
주문 상세
왼쪽 위 뒤로 버튼으로 목록에 돌아옵니다

04

뒤로 버튼 Back button

바로 앞에 봤던 화면으로 돌아가는 버튼. 보통 왼쪽 위 화살표(‹)이고, 화면 이동 기록을 한 칸 되감습니다. 취소와 달리 입력 중인 일을 포기하는 게 아니라 단지 이동 경로를 되돌립니다.

언제 쓰나목록에서 상세로 들어간 화면, 설정의 하위 페이지, 결제 단계의 이전 화면.

AI에게 이렇게상세 화면 왼쪽 위에 뒤로 버튼을 두고, 누르면 직전 목록 화면과 스크롤 위치로 돌아가게 해줘

20년차 메모뒤로 버튼이 앞 화면이 아닌 "홈"으로 가면 사용자는 길을 잃습니다. 안드로이드는 시스템 뒤로 키, iOS는 화면 왼쪽 가장자리 스와이프와도 같은 동작이어야 하고, 뒤로 갔을 때 입력 값과 스크롤이 남아 있어야 합니다. 라벨 대신 아이콘이면 aria-label에 "주문 내역으로 돌아가기"처럼 돌아갈 곳의 이름을 쓰세요.

05

다음·이전 버튼 Next · Previous

여러 단계나 여러 장으로 나뉜 내용을 앞뒤로 넘기는 한 쌍의 버튼. 뒤로 버튼은 "온 길을 되돌림"이고, 이 쌍은 같은 흐름 안에서 정해진 순서대로 오가는 점이 다릅니다. Pagination(쪽 넘기기)의 화살표도 같은 부류입니다.

언제 쓰나다단계 신청서, 튜토리얼 슬라이드, 갤러리, 검색 결과의 이전·다음 쪽.

AI에게 이렇게5단계 폼 아래에 이전·다음 버튼을 두고, 첫 단계에서는 이전을 비활성화하고 마지막 단계에서는 다음을 "제출하기"로 바꿔줘

20년차 메모마지막 단계에서도 "다음"이 남아 있으면 사용자는 아직 더 있는 줄 압니다. 끝에서는 라벨을 "제출하기"처럼 결과가 보이는 말로 바꾸세요. 이전은 약하게(세컨더리), 다음은 프라이머리로 두고, 이전으로 가도 입력한 값이 남아 있어야 합니다. 쪽 넘기기에서는 현재 쪽 번호가 눌린 것처럼 보여야 합니다.

사진을 한곳에 모아 보세요

06

건너뛰기 Skip

필수가 아닌 안내나 설정 단계를 넘기고 다음으로 가는 버튼. 취소와 달리 "하지 않겠다"가 아니라 "나중에 해도 된다"는 뜻이라, 대개 약한 텍스트 버튼으로 둡니다.

언제 쓰나온보딩 슬라이드, 프로필 사진 등록, 알림 권한 요청처럼 안 해도 서비스를 쓸 수 있는 단계.

AI에게 이렇게온보딩 오른쪽 위에 텍스트 형태의 건너뛰기 버튼을 두고 누르면 홈 화면으로 이동하게 해줘

20년차 메모건너뛰기를 숨기거나 회색으로 지우면 앱스토어에서도 사용자도 싫어합니다. 대신 건너뛴 사람이 나중에 그 기능을 다시 찾을 길(설정 화면의 "프로필 사진 등록하기")을 꼭 남기세요. 정말 필수인 단계에 건너뛰기를 두면 뒤에서 오류가 납니다. 라벨은 "나중에 하기"와 "건너뛰기" 중 하나로 통일하세요.

  • 후기 1 · 배송이 빨라요
  • 후기 2 · 포장이 꼼꼼해요
  • 후기 3 · 색이 사진과 같아요

07

더 불러오기 Load more

목록 끝에 놓인 버튼으로, 누르면 다음 몇 개를 이어서 불러와 아래에 붙입니다. 쪽 번호를 바꾸는 페이지네이션과 달리 기존 목록 아래로 계속 쌓이고, 자동으로 불러오는 무한 스크롤과는 사용자가 직접 누른다는 점이 다릅니다.

언제 쓰나후기, 댓글, 검색 결과처럼 한 번에 다 못 보여 주고 끝 지점을 사용자가 정하게 하고 싶을 때.

AI에게 이렇게후기 목록 아래에 "더 불러오기" 버튼을 두고, 누르면 로딩을 보여준 뒤 3개를 이어 붙이고 마지막에는 비활성화해줘

20년차 메모라벨에 "후기 더 불러오기"처럼 무엇이 몇 개 더 오는지 쓰면 좋고, 누른 직후에는 스피너로 반응해야 두 번 누르지 않습니다. 새 항목이 붙은 뒤 키보드 포커스를 첫 새 항목으로 옮겨 주지 않으면 스크린리더 사용자는 뭐가 늘었는지 모릅니다. 끝에 다다르면 버튼을 지우거나 "마지막까지 봤어요"로 바꾸세요. 푸터가 있는 페이지에서는 무한 스크롤보다 이 버튼이 푸터에 닿을 수 있어 낫습니다.

수령 후 7일 안에는 사용하지 않은 상품에 한해 환불할 수 있습니다. 배송비는 단순 변심일 때 본인이 부담합니다.

눌러 보세요. 화살표가 뒤집히며 열립니다

08

펼치기·접기 Expand · Collapse (chevron)

눌러서 숨은 내용을 열고 닫는 버튼. 옆의 아래 화살표를 셰브런(chevron)이라 부르고, 열리면 위쪽으로 뒤집힙니다. 여러 개를 묶으면 아코디언(Accordion)이 됩니다.

언제 쓰나자주 묻는 질문, 상품 상세 정보, 긴 약관, 필터 그룹처럼 한 번에 다 보여 주면 너무 길어지는 내용.

AI에게 이렇게FAQ 질문을 펼치기·접기 버튼으로 만들고 aria-expanded 와 셰브런 회전 애니메이션을 넣어줘

20년차 메모접힌 쪽의 라벨이 질문 전체여야 눌러 볼 이유가 생깁니다. "자세히 보기"만 쓰지 말고 "환불 규정 보기"처럼 내용을 예고하세요. 열린 상태는 aria-expanded로 알려야 하고, 접힌 내용 안의 링크가 탭 순서에 걸리지 않게 해야 합니다. 열렸는데 화살표가 그대로면 방향 신호가 거짓말이 됩니다. 라벨 자체를 "접기"로 바꿀 땐 셰브런 방향과 어긋나지 않게 하세요.

09

맨 위로 Back to top · Scroll to top

긴 페이지를 한참 내린 뒤 한 번에 맨 위로 올려 주는 버튼. 처음부터 보이지 않고 어느 정도 내려갔을 때만 나타나는 것이 보통입니다.

언제 쓰나끝없이 이어지는 목록, 긴 기사, 문서형 페이지, 후기가 수백 개인 상품 상세.

AI에게 이렇게300px 이상 스크롤하면 오른쪽 아래에 "맨 위로" 버튼이 나타나고, 누르면 부드럽게 맨 위로 올라가게 해줘

20년차 메모하단 고정 CTA 바나 FAB와 같은 자리에 겹쳐 놓는 실수가 흔하니 위치를 미리 나눠 두세요. 아이콘만 쓰면 위쪽 화살표의 뜻이 모호해서 "맨 위로"라는 글자를 붙이거나 aria-label을 꼭 달고, 스무스 스크롤은 "동작 줄이기" 설정을 켠 사용자에게는 끄세요. 모바일 브라우저는 상단 바를 탭하면 맨 위로 가므로 웹앱에서는 쓸모가 줄어듭니다.

10

더보기 버튼 More · Overflow (kebab)

자리가 모자라 다 못 보여 준 동작을 점 모양 아이콘 뒤에 모아 둔 버튼. 점 세 개를 세로로 두면 케밥(kebab), 가로로 두면 미트볼 또는 햄버거와 구분해 오버플로 메뉴라고 부릅니다.

언제 쓰나목록의 각 항목, 카드 모서리, 앱 상단바처럼 동작이 여럿인데 한두 개만 직접 보여 줄 수 있을 때.

AI에게 이렇게목록 항목 오른쪽에 케밥 더보기 버튼을 두고, 누르면 이름 바꾸기·공유하기·삭제하기 메뉴가 열리게 해줘

20년차 메모자주 쓰는 동작까지 메뉴 뒤에 숨기면 사용자는 기능이 없는 줄 압니다. 가장 많이 쓰는 한 가지는 밖으로 꺼내세요. 삭제는 메뉴 맨 아래에 빨간 글자로 두고 확인 단계를 한 번 더 두세요. 아이콘만이라 aria-label이 "더보기"가 아니라 "여행 사진 모음 더보기"처럼 대상이 들어가야 목록에서 구분됩니다. iOS는 가로 점 세 개(···), 안드로이드는 세로 점 세 개가 관습입니다.

npm run dev
눌러 보세요. 잠깐 "복사됨"으로 바뀝니다

11

복사 버튼 Copy button

글자나 링크를 클립보드에 담아 주는 버튼. 사용자가 드래그해서 복사할 수고를 없애고, 누르면 "복사됨"이라고 잠깐 알려 주는 것이 약속입니다.

언제 쓰나초대 코드, 계좌번호, 쿠폰 번호, 코드 예시, 공유 링크.

AI에게 이렇게코드 상자 오른쪽에 복사 버튼을 두고, 누르면 클립보드에 복사한 뒤 1.5초 동안 "복사됨"으로 바뀌게 해줘

20년차 메모누른 뒤 아무 반응이 없으면 사용자는 몇 번을 더 누릅니다. 글자는 "복사됨"으로 바꾸고, 스크린리더에는 aria-live로 같이 알리세요. 라벨은 처음엔 "복사"만 두면 되지만 무엇을 복사하는지 모호한 곳에서는 "초대 코드 복사"처럼 대상을 쓰세요. 클립보드 접근은 https 환경에서만 되고 권한이 막히면 실패하니, 실패하면 "직접 복사해 주세요"를 보여 주는 대비책이 필요합니다.

12

공유 버튼 Share button

지금 보는 글이나 상품을 다른 사람이나 다른 앱으로 보내는 버튼. 누르면 보통 공유 시트(Share sheet)라는 선택 창이 올라옵니다. 복사 버튼은 클립보드에 담기만 하고, 공유 버튼은 보낼 곳을 고르게 합니다.

언제 쓰나기사, 상품, 이벤트 페이지, 초대 링크처럼 다른 사람에게 건네고 싶은 내용.

AI에게 이렇게상세 페이지에 공유 버튼을 두고, 모바일에서는 기본 공유 시트를 열고 데스크톱에서는 링크 복사 메뉴를 보여줘

장바구니의 내용을 실제 돈으로 바꾸는 마지막 버튼. 화면 전체에서 가장 무겁고 신중해야 하는 프라이머리 버튼입니다. 장바구니 화면의 "주문하기(Checkout)"는 결제 화면으로 가는 버튼이고, 결제 화면의 "결제하기(Pay)"가 실제 결제입니다.

언제 쓰나결제 화면 맨 아래, 구독 시작, 충전, 송금 확인.

AI에게 이렇게결제 화면 맨 아래에 "12,000원 결제하기" 버튼을 고정하고, 누르면 잠그고 "결제 중"을 보여준 뒤 완료 화면으로 보내줘

20년차 메모라벨에 금액을 넣으면("12,000원 결제하기") 사용자가 무엇에 동의하는지 다시 보게 되어 분쟁이 줄어듭니다. 중복 클릭 방지가 가장 중요해서 누른 즉시 잠그고, 응답이 오래 걸려도 "창을 닫지 마세요"를 알리세요. 실패하면 카드가 승인됐는지 아닌지를 분명히 알려야 하며, 이 버튼을 닫기·취소와 같은 줄에 붙여 두지 마세요. 낙관적 UI는 결제에 쓰면 안 됩니다.

간편 로그인 버튼 Social login button

구글·애플·카카오 같은 이미 있는 계정으로 가입 없이 로그인하는 버튼. 비밀번호를 새로 만들지 않아도 되는 것이 장점이고, 제공 회사의 이름과 로고를 쓰는 규정이 따로 있습니다. 소셜 로그인, SSO 버튼이라고도 합니다.

언제 쓰나로그인·회원가입 화면의 맨 위쪽, 가입 장벽을 낮추고 싶을 때.

AI에게 이렇게로그인 화면에 "구글 계정으로 계속하기" 같은 간편 로그인 버튼을 세로로 쌓고, 누르면 "연결 중"을 보여준 뒤 계정 선택 창을 열게 해줘

20년차 메모"로그인"과 "가입"을 따로 두지 말고 "계속하기"로 통일하면 처음 온 사람과 돌아온 사람이 한 버튼으로 해결됩니다. 로고와 색은 각 회사가 정한 가이드를 따라야 하는데 임의로 바꾸면 심사에서 반려됩니다. iOS 앱이 다른 간편 로그인을 쓰면 애플 로그인도 함께 제공해야 하는 심사 규정이 있으니 출시 전에 확인하세요. 마지막에 어느 계정으로 로그인했는지 기억해 같은 버튼을 먼저 보여 주면 헷갈림이 줄어듭니다.
